# SDK 业务实战验收记录

验收日期：2026-10-10。目标：用公开接口实现一个完整业务模块，确认开发者不必引用引擎内部头文件。

## 被测业务

[区域持续占用示例](../../projects/modules/logic_roi_dwell_demo/README.md)：读取 Web 参数契约，
查询命名 ROI 中的目标，保存跨帧状态，持续达到阈值后绘图、发布变量并提交事件。
源码只包含三个 SDK 头文件和标准库；业务策略全部保留在 `projects/modules/`。

实际编译数据库中的两个业务目标 `vision_business`、`sdk_example_consumer` 均只包含
`engine/include` 和系统 OpenCV 搜索路径。测试夹具与业务分开编译，只有夹具能绑定内部上下文。

| 显示、图片、视频三种绘图出口 | 区域线和文字确实生成像素 |

## 对接口易用性的结论

这条业务流程可直接用现有 SDK 完成，没有发现必须补充引擎内部接口才能实现的步骤。
参数无需手动解析 JSON，状态无需管理裸指针分配，ROI 和绘图无需自行换算分辨率。
没有为这个示例增加公开业务函数、总入口头文件或转发头文件。

需要开发者明确的约定有三处：

1. 目标查询不替代推理有效性判断。报警前应检查 `infer_enabled`、`inference_valid` 和结果可用性。
2. 修改阈值是否清空计时是业务决策，应在 `logic.json` 明确 `x-hot-reload`。
3. 事件接受不等于远端收到；需要当前绘图的证据时，应先绘图再提交，已补充公开事件头文件说明。

## 验收范围

已通过完整引擎构建、两个 SDK 回归及原有 13 个回归，共 15 项；模块清单校验、文档审计和
`git diff --check` 通过。公开头文件检查涵盖独立编译与业务实际包含依赖。

本次不是 NPU 识别精度、真实告警存储/上传、GPIO 或浏览器端的端到端验收。
录像中的检测框是明确标注的可控输入；事件出口是记录请求和模拟返回值的测试接收器。
参数热更新验证覆盖真实 Schema 解析与策略计算，并由夹具按策略重建状态，没有运行配置监视线程。
因此上述结论针对 SDK 业务调用链及这条业务规则，不推断所有接口或生产环境都已验证。
