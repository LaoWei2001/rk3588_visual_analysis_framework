# Web 配置与底层状态自动同步排查

2026-10-16。范围为控制台所有配置入口，以及它们依赖的文件、内核接口、NetworkManager、systemd 和运行服务状态。

## 统一行为

- 可见浏览器页面每 1 秒发起同步；请求未完成时不叠加请求。切换目标、开始写操作、组件卸载后，旧轮询结果不再回写。
- 没有未保存编辑时，表单跟随底层变化。正在编辑时保留内容；底层对应配置变化后提示冲突，先重新同步再保存。
- 读取失败保留最近一次有效值，并提示数据可能过期；连接恢复后自动重试。未知状态不能当作关闭。
- 自动读取不修改持久配置、不触发重启、不扫描 Wi-Fi 或搜索摄像头。命令行的临时改动仍只在用户点击保存后持久化。
- 硬件看门狗和程序启动参数需要下一次启动才能应用；保留待生效配置，同时显示实际运行状态，避免轮询把待生效选择冲掉。
- 使用已有的服务端版本检查；其他保存入口先复核底层值，避免覆盖在最近一次轮询之后发生的修改。保存前复核不是所有外部写入者共同参与的原子事务。

## 排查结果与改动

| 配置入口 | 底层来源 | 发现的问题与处理 |
| --- | --- | --- |
| 系统崩溃恢复 | `/proc/sys/kernel/panic`、持久 sysctl 配置 | 开关原先只读保存值；现在跟随实际值，显示临时与持久配置差异，保留未保存编辑。 |
| 硬件卡死恢复 | systemd 看门狗实际超时、设备接管状态、持久策略 | 每秒刷新实际状态；硬件档位与请求值分别显示，保留待重启选择。 |
| 网络恢复 | `network-recovery.json`、独立服务状态 | 原先只初始化一次表单；现在干净表单每秒跟随策略，编辑冲突时禁止覆盖。 |
| 程序恢复 | `recovery.json`、当前程序的实际服务保护状态 | 原先只初始化一次表单；现在跟随文件变化，保留当前程序待应用状态及版本检查。 |
| 日期、时间、时区 | 系统时间、`/etc/localtime`、timedatectl | 每秒校准并同步干净表单，保留正在编辑的日期时间。支持按设备时区手动设时或按浏览器绝对时间同步；自动校时开启时明确提示并关闭，设时失败尝试恢复。时区或自动校时状态变化时阻止旧草稿提交。 |
| 每日定时重启 | systemd timer 的 ActiveState、TimersCalendar、UnitFileState | 原先开关取旧 JSON；现在取实际运行状态和日历时间，单列重启后配置差异，可保存当前选择。 |
| 主机名、有线、Wi-Fi、已保存连接 | hostname、NetworkManager 实际接口与连接参数 | 原先只读取一次，同一连接 UUID 下改 IP/DNS 不更新；现在每秒读取，按表单组保护编辑，保存前复核，保留网络事务确认与自动回滚。设备和连接的 nmcli 查询按组批量读取，旧厂商版本不支持时逐字段回退。 |
| 存储清理策略与磁盘用量 | 存储策略 JSON、磁盘空间 | 原先只读取一次，手动刷新会覆盖编辑；现在每秒轻量读取策略和磁盘。录像与开发缓存目录的递归盘点仍在初次加载或手动刷新执行。 |
| 性能与温控 | sysfs 实际频率上限与温度阈值、持久 profile | 已有每秒采样和版本检查；补充编辑期间的底层变化提示及保存阻止。 |
| 设备基本信息 | 主机名、接口、路由、时间同步、服务状态 | 原先页面与后端均缓存 15 秒；现在每秒读取，后端最多复用 1 秒内的同一份概况。 |
| 程序管理、自启、运行配置 | 运行管理器意图文件、实际进程与 systemd 状态 | 原先 5 秒更新；现在每秒更新，动作期间隔离旧轮询结果，失败时显示过期提示。手动选中的下次启动配置仍作为待执行选择保留。 |
| 后台服务 | systemd 实际状态、平台编排意图文件 | 原先 5 秒更新且静默忽略错误；现在每秒读取并显示失败提示。应用服务的自启由平台编排管理，与 systemd 单元 enabled 分别显示。 |
| 摄像头网络配置 | 摄像头配置文件、物理网口、ARP/HTTP/RTSP 状态 | 原先只刷新探测状态，表单和网口列表不更新；现在每秒读取完整快照，保护编辑；不会自动发现、规划或应用网络修改。探测超时时等待当前请求完成。 |
| 画布、全局参数、节点、ROI | 当前选中的配置 JSON | 原先打开时读取一次；现在外部文件更新会同步到干净画布，编辑时保留并提示冲突，保存前复核；取消了打开页面时自动创建或覆盖缺失配置的行为。保存期间新增编辑仍保持未保存状态。 |
| 模型、素材、通道与全局逻辑清单 | 素材目录、`logics.json`、模型文件版本及运行模型状态 | 原先多处只读一次；现在每秒同步素材、清单和模型状态。模型元数据仍利用按文件版本建立的后端缓存，不重复解析未变化模型。 |
| 应用集成：投递连接、OTA | `connections.yaml`、OTA JSON | 原先只在弹窗打开时读取；现在每秒更新，保留编辑、提示冲突，保存前复核。 |
| 上报接口模板 | 包内与自定义契约文件、契约修订 | 清单及打开的模板每秒跟随文件变化；保留模板编辑，外部变更时阻止覆盖；后台只读不会发送测试请求。 |
| 数据集采集任务 | 任务数据库、视觉程序采集状态 | 原先 2 秒状态刷新，已打开编辑器不更新；现在每秒同步，干净编辑器跟随任务配置，编辑冲突或外部删除时保留并提示，保存前复核。 |
| 独立视频采集 | 独立采集器实际状态、USB 设备目录 | 实际预览/录像状态原本已每秒读取；补齐动作与旧读请求隔离、读取错误提示和 USB 设备列表同步。视频来源输入是下一次连接请求，当前实际来源及参数在预览状态中显示。 |
| 实时画面控制 | 当前程序与控制 socket | 程序及控制状态由 3 秒改为每秒；程序 PID 改变时重新读取运行配置。播放进度保持已有更快刷新。 |

浏览器自身的面板宽度、过滤条件、下载平台、待提交的密码或新建任务参数没有对应的底层生效配置，继续作为浏览器偏好或草稿保存。
日志、历史、告警记录不是配置项，保留各自读取频率。

## 系统时间修改

“系统设置 → 系统 → 日期与时间”提供精确到秒的日期时间输入和“与当前电脑同步”。电脑同步提交 Unix 毫秒时间戳，不把浏览器所在时区当作设备时区。手动输入按设备当前 IANA 时区解释；不存在或含糊的夏令时日期会被拒绝。

`PUT /api/system/time` 仅允许 root、sudo 或 wheel 管理员，使用 `timedatectl set-time` 同时更新系统时钟和硬件时钟。提交前复核时区和自动校时状态；网络校时状态无法读取时禁止写入。手动校时会影响日志及每日定时重启的执行时刻。登录有效期使用单调时钟，避免调整日期导致会话立即过期或额外延长。

相关测试模拟所有设时命令和浏览器写接口，不修改测试设备的实际时钟、时区或网络校时状态。

## 验证

- 前端 TypeScript 检查与生产构建。
- 浏览器隔离测试模拟命令行/外部进程改动：时区、每日重启、存储、主机名、同 UUID 的网络参数、摄像头配置、自启、画布和 OTA。
- 检查未保存编辑保留、明确重新同步、保存前复核、读取失败后自动恢复，确认轮询没有产生写请求或设备操作。
- 现有恢复管理、性能、数据集工作流、系统设置、摄像头和自启回归测试。
- 后端测试验证 timer 状态覆盖旧 JSON，以及每秒存储读取不会递归扫描媒体或 root 缓存。
- 本板批量读取与原逐字段读取返回的网络快照完全一致；读取耗时由约 1.7 秒降至约 0.37 秒（4 张网卡、2 个连接配置）。
- 最终生产构建通过；80 项浏览器回归、152 项相关后端与运行库测试通过。测试使用隔离配置及模拟设备操作。
