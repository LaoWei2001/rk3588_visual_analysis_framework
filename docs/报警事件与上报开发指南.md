## 一、先建立正确概念

当前框架没有为某个客户或某种报警保留一套专用 `alarm_xxx` 上报模块。统一模型是：

```text
视频帧 / 模型结果
  -> channel/global logic 判断是否发生业务事件
  -> EventRequest 描述事件和算法变量
  -> report_event() 创建本地持久化事件
  -> 图片/视频异步生成
  -> EventOutboxForwarder 等待媒体并维护重试状态
  -> adapter 按 Profile + 接口契约投递
  -> HTTP 服务器或 Dify 工作流
```

各层只负责一类问题：

| 层 | 负责 | 不负责 |
|---|---|---|
| `logic.cpp` | 报警条件、计时/闩锁、算法动态字段、报警画面绘制 | URL、Header、API Key、Base64、网络重试 |
| `logic.json` | 参数、按钮、`report_fields` 字段声明 | 运行时真实数值、远端字段名 |
| `report_event()` | 事件建档、合并、媒体任务、本地持久化 | 直接联网、判断远端成功 |
| Profile | URL、密钥、Header、超时 | 业务 JSON 字段 |
| 接口契约 | 固定值、字段名、嵌套结构、媒体、转换、成功条件 | 算法计算、连接密钥 |
| adapter | HTTP/Dify 交互步骤 | 报警条件 |
| Web | 参数、Profile/契约选择、契约编辑、预览和测试 | 在浏览器中执行算法 |

必须记住：

```text
report.accepted() == 本地事件已进入发件箱
report.accepted() != 服务器或 Dify 已经收到
```

## 二、五分钟完成一个最小报警

### 2.1 在 logic 中提交事件

业务模块位于：

```text
vision_analysis/src/logic/modules/logic_xxx/
├── logic.cpp
└── logic.json
```

最小 C++ 示例：

```cpp
#include "logic/core/logic_common.h"

static void logic_person_intrusion(ChannelContext *ctx)
{
    if (!ctx || !ctx->frame || ctx->frame->empty() || !ctx->results)
        return;

    const AlgoResult *hit = nullptr;
    for (const auto &result : *ctx->results)
    {
        if (result.label != "person")
            continue;
        hit = &result;
        break;
    }
    if (!hit)
        return;

    /* 必须先绘制，再创建事件，本次媒体才能包含这些内容。 */
    draw_rect(ctx, hit->box, cv::Scalar(0, 0, 255), 3,
              1.0, DrawCommand::MEDIA);
    draw_text(ctx, "人员入侵", cv::Point(20, 50),
              cv::Scalar(0, 0, 255), 0.8, 2, DrawCommand::MEDIA);

    EventRequest request;
    request.event_type = "person_intrusion";
    request.message = "检测到人员进入危险区域";
    request.fields = {
        event_field("label", hit->label),
        event_field("score", hit->score),
        event_field("track_id", hit->track_id),
    };

    const EventReportResult report = report_event(ctx, request);
    if (!report.accepted())
    {
        fprintf(stderr, "[person_intrusion][ch%02d] report failed: %s (%s)\n",
                ctx->chnId, event_report_status_name(report.status),
                report.detail.c_str());
    }
}

REGISTER_LOGIC(logic_person_intrusion);
```

实际业务必须增加闩锁、冷却或按 `track_id` 去重，不能在条件持续成立时每帧创建事件。ROI、坐标、
状态和参数的完整规则继续阅读
[通道逻辑开发](skills/rk3588-channel-logic/SKILL.md)。

### 2.2 声明事件类型和 Web 可见字段

同目录 `logic.json`：

```json
{
  "label": "人员入侵",
  "parameters": {
    "type": "object",
    "additionalProperties": false,
    "properties": {}
  },
  "event_types": [
    {
      "id": "person_intrusion",
      "label": "人员入侵",
      "help": "人员进入配置的警戒区域时产生。"
    }
  ],
  "report_fields": [
    {"key": "label", "type": "string", "label": "目标类别"},
    {"key": "score", "type": "number", "label": "置信度"},
    {"key": "track_id", "type": "number", "label": "跟踪 ID"}
  ]
}
```

`event_types[].id` 必须与 C++ `EventRequest.event_type` 完全一致。Web 上报节点只允许从这里
声明的事件类型中选择，不再要求开发者手工输入字符串。一个 logic 不产生事件时也必须显式写
`"event_types": []`；构建目录生成器会拒绝“调用了 `report_event()` 但没有声明事件类型”的模块，
并检查 C++ 中直接使用的事件类型字符串是否已经声明。

`report_fields[].key` 必须与 C++ `event_field()` 的 key 相同，类型只能是
`string/number/boolean/json`。

```text
logic.json.report_fields -> 告诉 Web 有哪些算法变量
EventRequest.fields      -> 事件触发时写入真实值
```

仅在 `logic.json` 声明字段不会自动计算数值；仅在 C++ 写字段但不声明，会导致 Web 契约编辑器
无法用中文名称列出该变量。

### 2.3 在 Web 完成接线

1. 重新构建、安装 App，确保生成的 `logics.json` 包含新模块；
2. 在 Web 画布选择该 logic；
3. 从 logic 节点连接“上报配置”节点；
4. 选择发送 Profile；
5. 选择已有接口契约，或点击“新建接口模板”；
6. “接收的事件类型”默认选择全部；确需分流时再勾选 `logic.json.event_types` 中的子集；
7. 保存画布；
8. 启动 App 和事件投递服务；
9. 按“本地事件 → 请求预览 → 测试发送 → 远端记录”逐层验证。

## 三、事件中有哪些数据

### 3.1 logic 自己填写的数据

通道 logic 常用 `EventRequest` 的四项业务职责：

```cpp
EventRequest request;
request.event_type = "person_intrusion";  // 稳定机器标识
request.message = "检测到人员进入禁区";    // 人类可读说明
request.fields = { /* 算法动态字段 */ };
request.merge_mode = EventMergeMode::POLICY;
```

全局 logic 还可设置 `request.source_channel_id`，选择事件来源标识和单通道事件视频；省略时使用
全局上报节点保存的默认来源或首个输入通道。全局告警图片仍拼接该实例的全部输入通道。通道 logic
无需设置这个字段，始终使用 `ctx->chnId`。

字段写法：

```cpp
request.fields = {
    event_field("name", std::string("camera-a")),
    event_field("count", 3),
    event_field("score", 0.93),
    event_field("active", true),
    event_json_field("detections", R"([{"label":"person","score":0.93}])"),
};
```

也可以逐项设置：

```cpp
request.fields.set_string("name", "camera-a");
request.fields.set_number("count", 3);
request.fields.set_bool("active", true);
request.fields.set_json("detections", detections_json);
```

JSON 字符串必须是合法对象、数组或 JSON 值；不要把普通文本误用 `event_json_field()`。

### 3.2 框架自动补充的数据

事件落盘后可供契约选择的常用 source：

| source | 内容 |
|---|---|
| `event.id` | 本地唯一事件 ID |
| `event.type` | `EventRequest.event_type` |
| `event.message` | `EventRequest.message` |
| `event.trigger_unix_ms` | 触发毫秒时间戳 |
| `event.last_trigger_unix_ms` | 最近合并触发时间 |
| `event.trigger_count` | 合并触发次数 |
| `event.snap_time` | 抓拍可读时间 |
| `event.end_time` | 事件结束可读时间 |
| `source.channel_id` | 通道 ID |
| `source.parameters.<key>` | 通道 `report_parameters` |
| `fields.<key>` | C++ 自定义算法字段 |
| `event`、`source`、`fields` | 整体对象 |
| `media.annotated_image` | 带叠加图片 |
| `media.raw_image` | 未叠加图片；通道事件为模型输入尺寸，全局事件为多窗格拼图，不等于摄像头原分辨率 |
| `media.video` | 事件 MP4 |
| `constant` | 契约中填写的固定值 |

## 四、自动、周期和按钮触发

### 4.1 自动报警

检测条件成立时调用 `report_event()`。必须使用每通道 `ctx->state` 保存闩锁、计时和目标去重，
不要使用可变 `static`。

推荐状态骨架：

```cpp
struct AlarmState
{
    bool latched = false;
    uint64_t last_report_ms = 0;
};

AlarmState &alarm_state(ChannelContext *ctx)
{
    if (!*ctx->state)
        *ctx->state = std::make_shared<AlarmState>();
    return *std::static_pointer_cast<AlarmState>(*ctx->state);
}
```

`ctx->state` 的声明类型是 `std::shared_ptr<void> *`：它是指向智能指针对象的指针，所以读取和
替换其中的智能指针需要 `*ctx->state`。业务代码不拥有这个外层指针的生命周期。

### 4.2 周期事件

参考：

- C++：`vision_analysis/src/logic/modules/logic_periodic_snapshot_demo/logic.cpp`
- 字段声明：同目录 `logic.json`
- 说明：[周期截图示例](skills/rk3588-channel-logic/references/examples/logic_periodic_snapshot_demo.md)

该模块每个周期写入：

```text
fields.display_number
fields.report_interval_sec
fields.report_sequence
```

并设置 `EventMergeMode::NEVER`，确保每个周期创建独立事件。

### 4.3 Web 按钮触发

按钮不能在 HTTP 路由或 action handler 中直接截图、编码或联网。按钮只改变当前通道状态，
下一张有效业务帧再创建事件。

`logic.json`：

```json
"actions": [
  {
    "id": "trigger_report",
    "label": "立即生成报警",
    "style": "primary",
    "help": "在下一张有效业务帧创建事件"
  }
]
```

C++：

```cpp
struct ButtonAlarmState
{
    bool pending_report = false;
};

ButtonAlarmState &button_alarm_state(ChannelContext *ctx)
{
    if (!*ctx->state)
        *ctx->state = std::make_shared<ButtonAlarmState>();
    return *std::static_pointer_cast<ButtonAlarmState>(*ctx->state);
}

ChannelActionResult logic_xxx_action(ChannelContext *ctx,
                                     const ChannelAction *action)
{
    ChannelActionResult result;
    if (!ctx || !ctx->state || !action)
    {
        result.message = "ctx or action is null";
        return result;
    }
    if (action->name != "trigger_report")
    {
        result.message = "unsupported action: " + action->name;
        return result;
    }

    button_alarm_state(ctx).pending_report = true;
    result.handled = true;
    result.message = "报警事件已排队";
    return result;
}
```

逐帧 logic：

```cpp
ButtonAlarmState &state = button_alarm_state(ctx);
if (!state.pending_report)
    return;

EventRequest request;
request.event_type = "manual_alarm";
request.message = "Web 按钮触发";
request.merge_mode = EventMergeMode::NEVER;
const EventReportResult report = report_event(ctx, request);
state.pending_report = false;
```

文件末尾同时注册：

```cpp
REGISTER_LOGIC(logic_xxx);
REGISTER_LOGIC_ACTION(logic_xxx, logic_xxx_action);
```

动作会在该通道下一次 logic 调用前执行，不会在 Socket 线程中并发修改 `ctx->state`。正式参考是
`logic_upload_teach`，更完整说明见
[自定义按钮动作](skills/rk3588-channel-logic/references/custom-button-actions.md)。

## 五、图片和视频

### 5.1 媒体由契约决定

logic 不设置“发图片还是视频”。接口契约声明：

```json
"media": ["annotated_image", "raw_image", "video"]
```

Web 保存 delivery 时只保留 C++ 必须提前知道的媒体快照：

```json
{
  "id": "delivery_1",
  "enabled": true,
  "profile_id": "factory_http",
  "contract_id": "server_person_alarm",
  "media": ["annotated_image"],
  "when": {
    "event_types": ["person_intrusion"]
  }
}
```

adapter、mapping、request 和 success 不复制进 delivery；它们只存在于契约。

### 5.2 绘制顺序

希望报警图片或视频包含业务文字/框时：

```text
draw_*()
  -> report_event()
```

不能先创建事件再绘制。常用 target：

| target | 用途 |
|---|---|
| `DrawCommand::DISPLAY` | 实时显示层 |
| `DrawCommand::IMAGE` | 报警图片 |
| `DrawCommand::VIDEO` | 事件视频 |
| `DrawCommand::MEDIA` | 图片 + 视频 |
| `DrawCommand::ALL` | 显示 + 图片 + 视频 |

### 5.3 媒体状态

图片和视频使用相同终态模型：

```text
requested -> generating -> ready
                        \-> failed
```

上传服务只在媒体 `ready` 后发送；生成失败会使需要该媒体的 delivery 进入 `failed`，不会永久等待。
视频还会等待事件前后窗口并异步编码。

## 六、Web 中配置接口

### 6.1 Profile 只保存连接

HTTP：

```yaml
profiles:
  factory_http:
    adapter: http_json
    url: http://192.168.2.22:9200/api/objectInvadeDet
    timeout: 15
    headers:
      Authorization: Bearer replace-me
```

Dify：

```yaml
profiles:
  inspection_dify:
    adapter: dify_workflow
    api_url: http://dify.example.com
    api_key: app-xxxxxxxx
    timeout: 120
```

Profile 不保存远端业务字段或成功 JSON 条件。

### 6.2 契约编辑器

选择上报节点后：

1. 先选择 Profile，Web 据此确定 `http_json` 或 `dify_workflow`；
2. 点击“新建接口模板”或“编辑当前模板”；
3. source 下拉框自动合并：
   - 系统事件；
   - 当前 logic 的 `report_fields`；
   - 图片/视频；
   - 固定值；
4. 填写远端字段名，点路径可生成嵌套 JSON，如 `alarmData.score`；
5. 选择类型和内容转换；
6. 勾选必填；
7. 保存模板；
8. 保存画布，使媒体快照同步给 C++；
9. 用“预览请求”检查最终数据；
10. 重启事件投递服务，使正式发件箱重新加载契约。

Web 保存的是已安装 App：

```text
/opt/ai_apps/.data/<App>/contracts/<contract_id>.json
```

Web 管理的 `.data/<App>/` 在覆盖或重装同名程序包时保留；程序包内模板只在首次迁移时初始化。
确认要随代码评审、版本管理和新 App 分发的模板仍应同步回仓库：

```text
service/upload/contracts/
```

## 七、HTTP 服务器适配

### 7.1 动态值、固定值和新增必填字段

假设服务器要求：

```json
{
  "source": "JNU",
  "alarmType": "person_intrusion",
  "alarmTime": "2026-07-30 21:30:00",
  "wei123": "required-value",
  "alarmData": {
    "score": 0.93
  },
  "image": "Base64..."
}
```

契约：

```json
{
  "id": "server_person_alarm",
  "label": "人员报警服务器",
  "adapter": "http_json",
  "media": ["annotated_image"],
  "request": {
    "method": "POST"
  },
  "mapping": [
    {"source": "constant", "target": "source", "value": "JNU", "required": true},
    {"source": "event.type", "target": "alarmType", "required": true},
    {"source": "event.snap_time", "target": "alarmTime", "required": true},
    {
      "source": "constant",
      "target": "wei123",
      "value": "required-value",
      "type": "string",
      "required": true
    },
    {
      "source": "fields.score",
      "target": "alarmData.score",
      "type": "number",
      "required": true
    },
    {
      "source": "media.annotated_image",
      "target": "image",
      "transform": "base64",
      "required": true
    }
  ],
  "success": {
    "http_status": [200],
    "json_path": "code",
    "equals": 200
  }
}
```

变化处理原则：

| 后端变化 | 修改位置 | 是否改 C++ |
|---|---|---|
| 增加固定必填字段 | Web 契约编辑器增加 `constant` | 否 |
| 字段改名或嵌套变化 | 修改契约 target | 否 |
| 使用已有时间/类型/通道 | 选择 `event.*` 或 `source.*` | 否 |
| 使用已有算法变量 | 选择 `fields.*` | 否 |
| 需要算法尚未计算的新变量 | C++ `EventRequest.fields` + `logic.json.report_fields` | 是 |
| URL、Token、Header 变化 | Profile | 否 |
| 图片/视频变化 | 契约媒体 + 保存画布 | 否 |
| 全新签名或交互协议 | 新 adapter | 通常不改 logic |

HTTP JSON 没有文件映射时使用普通 JSON Body。使用 `file` 转换时，adapter 发送 multipart，
结构化字段放在名为 `payload` 的 JSON 字符串字段中；后端必须按这一约定解析。

## 八、Dify 工作流适配

### 8.1 纯数据

Dify 工作流输入：

```text
event_json
fields_json
```

契约：

```json
{
  "id": "dify_event_data",
  "label": "Dify 标准事件数据",
  "adapter": "dify_workflow",
  "media": [],
  "mapping": [
    {
      "source": "event",
      "target": "event_json",
      "transform": "json_string",
      "required": true
    },
    {
      "source": "fields",
      "target": "fields_json",
      "transform": "json_string",
      "required": true
    }
  ]
}
```

这种形式适合在 Dify 代码节点中解析完整算法结果。

### 8.2 图片或视频

Dify 文件变量必须使用 `file`：

```json
{
  "source": "media.annotated_image",
  "target": "snapshot_image",
  "transform": "file",
  "file_mode": "single",
  "required": true
}
```

视频：

```json
{
  "source": "media.video",
  "target": "alarm_video",
  "transform": "file",
  "file_mode": "single",
  "required": true
}
```

实际流程：

```text
等待 jpg/mp4 ready
  -> POST /v1/files/upload
  -> 取得 upload_file_id
  -> 写入 Dify inputs 对应 target
  -> POST /v1/workflows/run（blocking）
```

`file_mode=list` 会把文件对象包装成数组，必须与 Dify 工作流变量类型一致。

Dify 字段增删只编辑 mapping；图片/视频变化还需保存画布以更新 C++ 媒体快照。只有 Dify 不再
使用标准文件上传/工作流执行接口，或加入特殊签名、多阶段业务交互时，才修改 adapter。

## 九、事件返回、合并和状态

### 9.1 C++ 返回结果

| 状态 | 含义 |
|---|---|
| `CREATED` | 新事件已持久化 |
| `MERGED` | 合并进同通道、同类型的活动事件 |
| `CREATED_MEDIA_FAILED` | 事件已保存，但媒体任务立即失败；`accepted()` 仍为真 |
| `DISABLED` | `report_policy` 关闭 |
| `NO_DELIVERY` | 没有匹配事件类型的有效 delivery |
| `INVALID_REQUEST` | ctx、配置或事件类型无效 |
| `WORKER_UNAVAILABLE` | 图片工作线程不可用 |
| `STORAGE_ERROR` | 事件目录或状态文件写入失败 |

`EventMergeMode::POLICY` 使用策略中的合并窗口；同一通道、同一事件类型可能返回 `MERGED`。
按钮测试、周期采样等每次都要独立记录的事件使用：

```cpp
request.merge_mode = EventMergeMode::NEVER;
```

### 9.2 事件目录

```text
event_store/<event_id>/
├── event.json
├── media_state.json
├── delivery_state.json
├── annotated.jpg
├── raw.jpg
└── clip.mp4
```

文件所有权：

| 文件 | 写入者 |
|---|---|
| `event.json` | C++ 事件模块 |
| `media_state.json` | C++ 图片/录像模块 |
| `delivery_state.json` | Python 投递服务 |
| `delivery_retry.request.json` | Web 请求重试，Python 消费 |

所有 delivery 成功后，当前实现删除整个事件目录。因此 Web“待上报记录”不是成功历史页面；
成功结果应同时查看上传服务日志和远端回执。

网络错误、HTTP 408/425/429 和服务器 5xx 会按 10 秒起步、最长 5 分钟的指数退避持续重试，
断网一天后也没有按次数永久停止；但能否补报还取决于 `.data/<App>/event_store/` 中记录是否仍在、
上传服务是否恢复、Profile/契约是否仍有效，以及发件箱是否因默认 1 GiB 容量或最低 512 MiB
磁盘余量触发了旧记录回收。

### 10.1 构建和安装

C++、模块 `logic.json` 或仓库内接口契约变化后：

`install_app.sh` 遇到同名 App 会询问是否覆盖；覆盖会先删除旧 App。先备份只存在于已安装 App

部署后浏览器执行硬刷新，再重启目标 App 和绑定到它的事件投递服务。只修改已安装 App 的 Profile

### 10.2 推荐验证顺序

```text
1. logic 是否进入触发条件

3. event.json 中 event/source/data.fields
```

### 10.4 常见错误

- 在 logic 中直接调用 HTTP、Dify 或 Base64；
- 把 URL、API Key、Header 写进 `logic.json.parameters`；
- C++ `event_field()` 与 `logic.json.report_fields` 名称或类型不一致；
- 每帧重复提交报警，没有闩锁/冷却/目标去重；
- 绘制发生在 `report_event()` 之后；
- 契约引用图片/视频，但 media 没有启用；
- 修改契约媒体后没有保存画布，导致 C++ 仍使用旧媒体快照；
- 修改契约后没有重启投递服务；
- Dify 工作流变量是文件，但契约没有使用 `transform=file`；
- 把 `accepted()` 当成远端成功；
- 手改 App 根目录生成的 `logics.json`；
- 为兼容旧代码重新引入第二套上报 API、旧通道 URL 字段或业务专用 uploader。

````text
## 架构硬约束
1. channel logic 只判断业务、绘制、维护每通道状态并调用 report_event()。
2. logic 中禁止 HTTP、Dify、Base64、阻塞网络、视频编码和连接密钥。
3. 事件只使用 EventRequest；所有算法动态值写入 fields。
4. EventRequest.event_type 必须在本模块 logic.json.event_types 中声明；
   event_field 的 key/type 必须与 logic.json.report_fields 一致。
5. URL、Header、Token、API Key 只放 Profile。
6. 固定字段、远端字段名、嵌套结构、媒体、转换和成功条件只放接口契约。
7. delivery 只保存 profile_id、contract_id、media 快照和可选事件过滤，不复制
   adapter/mapping/request/success。
8. 新增固定字段或远端改名不得修改 C++；只有算法尚未产生的新动态值才修改
   EventRequest.fields。
9. 按钮 handler 只设置 ctx->state；依赖画面的事件在下一张有效帧创建。
10. 跨帧状态使用 ctx->state，不使用可变 static。
11. 绘制必须发生在 report_event() 之前，并明确 DrawCommand target。
12. 必须检查 EventReportResult，不得把 accepted() 描述成远端成功。
13. 不增加旧接口兼容分支，不创建第二套报警/上报链路。
14. 保留工作区中与本任务无关的已有修改。
````
