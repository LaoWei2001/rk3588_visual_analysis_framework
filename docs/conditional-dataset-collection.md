# 条件式训练样本采集器

需求：复用模型检测结果，用用户配置的类别存在、缺失、数量与逻辑组合，自动筛选值得人工检查和补标的原始帧。检测结果是采集依据，不是人工确认的真实标签。

## 条件语义

规则针对同一通道、同一帧、明确选定模型的有效推理结果执行。`present(C)` 表示类别 C 达到该条件的最低置信度且数量至少为 1；`absent(C)` 表示在同样的置信度和区域约束下数量为 0。

组合操作为 ALL（并且）、ANY（或者）、NOT（取反），可嵌套。基础条件还支持数量比较（等于、不等于、大于、大于等于、小于、小于等于），每条条件可独立设置置信度。

| 用户意图 | 条件 |
| --- | --- |
| x、y、z 均出现，a、b 均缺失 | ALL(present(x), present(y), present(z), absent(a), absent(b)) |
| x 或 y 至少一类缺失 | ANY(absent(x), absent(y)) |
| x、y 都缺失 | ALL(absent(x), absent(y)) |
| x、y 至少一类出现，而 a 缺失 | ALL(ANY(present(x), present(y)), absent(a)) |
| 有人，但没有可见安全帽或未佩戴头部 | ALL(present(person), absent(helmet), absent(bare_head)) |

不存在于选定模型类别表中的名称属于配置错误；推理暂停、尚无结果、断流、推理失败与过期结果属于未知状态，均不得按“数量为零”触发缺失规则。规则阈值不得低于模型输出过滤阈值而声称仍能使用被过滤的检测框。

第一版明确支持全画面的类别与数量组合。按人员关联的条件必须单独表达，例如“至少一名 ROI 内人员没有关联安全帽”，不能用 `present(person) AND absent(helmet)` 冒充；后者只表示整幅图没有帽子。关联条件需要可配置的空间匹配及多目标归属策略。

## 通道逻辑配置示例

在通道逻辑节点选择 `logic_dataset_collector`（条件式数据采集）。该通道原业务逻辑会被替换；若同时需要告警与采集，可以另建采集通道，同来源 RTSP 仍复用项目已有的采集解码机制，但新通道推理会增加负载。

采集通道第一版只允许一个启用的检测模型，因为当前多模型合并结果没有每个子模型的成功标志，无法可靠区分“某个模型失败”和“该模型没有检测到目标”。未训练第三类的两类模型不能使用 `bare_head` 条件。

```json
{
  "enabled": true,
  "rules": [{
    "id": "unknown_helmet_state",
    "name": "人员存在但头部状态无法判断",
    "condition": {"all": [
      {"class": "person", "min_confidence": 0.3, "count": {"op": ">=", "value": 1}},
      {"class": "helmet", "min_confidence": 0.3, "count": {"op": "==", "value": 0}},
      {"class": "bare_head", "min_confidence": 0.3, "count": {"op": "==", "value": 0}}
    ]}
  }],
  "trigger_mode": "periodic",
  "confirm_sec": 0,
  "interval_sec": 2,
  "max_gap_sec": 2,
  "max_samples": 500,
  "max_store_mb": 1024,
  "save_dir": "/userdata/my_dataset",
  "save_metadata": false,
  "save_prediction": false
}
```

此规则采集“模型无法给出安全帽状态”的候选样本，不证明人员未佩戴或头部不可见。判断默认针对模型实际推理/输出范围，推理 ROI 限制输出时，缺失不代表全原图缺失。可填写 `roi_name` 将计数范围进一步限制在已绘制区域，`roi_anchor` 选择中心点或脚点。

## 采样行为

- 每个来源帧只评估一次，杜绝用同一帧重复累计持续时间、重复保存。
- 触发方式：刚进入满足状态时保存一次，或持续满足时按间隔采集；持续确认时间可设为零。
- 连续性按有效推理帧判断，出现中断、配置变化、视频跳转时重置确认状态，防止缺失条件误触发。
- 每个通道逻辑运行有采集数量上限，每个通道的图片保存目录有容量限制；达到限制停止保存并显示原因。数量上限在重启/配置重置后重新累计；容量限制包含已有样本。
- 同一帧命中多条规则只保存一份原图，元数据保存所有命中规则，避免重复占用存储。
- 第一版通过最小采样间隔控制重复帧，不做图像相似度去重。
- 规则和图片来自同一份不可变 publication；命中后才物化原始分辨率 BGR，JPEG 编码与保存交给有界后台队列，不在推理热路径重新运行模型或同步写盘。
- 采集内容使用单路原始画面，不使用多通道拼图、实时画面上的检测框或 FPS 文字作为训练图片。

## 输出与运行方式

在通道逻辑节点选择 `logic_dataset_collector`（条件式数据采集）。主界面分为“什么时候抓图”和“图片怎么保存”：每行填写类别并选择“检测到”或“没检测到”，选择“全部满足”或“任一满足”，界面实时显示完整抓图条件。保存文件夹、抓图间隔和最多保存张数直接可见。目标数量、置信度与嵌套条件放在“更多条件设置”，ROI、确认时间、容量、候选标注等放在“高级设置”。已有复杂规则完整保留，展开后编辑；高级条件也使用“检测到 / 没检测到 / 按指定数量判断”的表达，置信度以百分比填写（30 表示 0.3），内部配置仍保存 0～1 的原值。组合方式用完整句子说明，嵌套与反向判断单独折叠；条件组名称只用于备注，不决定判断逻辑。多组条件之间仍然是“或”。没有专用样本页面、程序管理按钮或样本 HTTP API。

“RK3588图片保存目录”对应 `save_dir`，填写板端绝对路径，自动按 `ch0`、`ch1` 等通道建立子文件夹。留空时默认 `/userdata/rk3588_dataset_samples/<程序名>/ch<通道号>`；程序名来自引擎工作目录名，Web 启动时为所选程序。手动启动可通过 `DATASET_STORE_DIR` 设置默认根目录；参数 `save_dir` 优先。

默认仅保存原始分辨率 JPG。所有图片直接位于通道文件夹，不再为每帧建立独立文件夹。文件名包含帧时间、会话身份、通道与帧号，避免多个来源或重启后相互覆盖。已有版本保存的文件不会被删除或自动迁移。

可选打开 `save_metadata`，保存同名 JSON，记录通道、来源帧时间与编号、模型身份、规则快照、命中原因、检测类别/置信度/框、图像尺寸与坐标转换信息。可选打开 `save_prediction`，保存同名 YOLO 候选 `.txt` 与 `.labels.txt` 类别表；两个开关默认关闭。候选标注包含该模型在完整原图坐标系下的全部输出框；计数 ROI/规则置信度只筛选帧，不删除原图上的其他预测框。

模型预测不是人工确认的标签，漏检目标仍须人工补标。类别编号保持模型原编号，不混合多模型类别表。使用者可以通过 SSH/SFTP 在 RK3588 查看或取走文件，再在电脑进行标注。

后台编码队列最多保留两帧（含正在处理的一帧），原图总内存最多 64 MB。满队列时跳过当前采样机会，不积累待处理视频。JPEG 和同名可选文件先写临时文件，最后原子提交 JPG；存盘失败不留下半张 JPG，不自动清理已有采集图片。数据盘预留至少 256 MB。

实时画面显示采集状态、保存数量与错误原因；声明的 `collector_*` 输出可供其他逻辑读取。图片保存独立于告警箱和上传服务，不创建告警或上传到服务器。

## 验证范围

用类别 x/y 四种存在组合验证 ANY/ALL 缺失规则，验证嵌套 NOT、计数、不同置信度与区域；验证未知类别、无推理、空但有效的推理、旧帧、中断及多模型来源。采样验证首次命中、持续确认、间隔、限额、队列压力和多规则单帧保存。真实视频验证保存原图与触发结果属于同一帧，默认仅生成 JPG、可选标注和命中信息的开关有效。
