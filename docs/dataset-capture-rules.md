# 数据集采集条件

Web 数据集采集复用模型检测结果，用用户配置的类别存在、缺失、数量与逻辑组合，自动筛选值得人工检查和补标的原始帧。检测结果是采集依据，不是人工确认的真实标签。

## 条件语义

规则针对同一通道、同一帧、明确选定模型的有效推理结果执行。`present(C)` 表示类别 C 达到该条件的最低置信度且数量至少为 1；`absent(C)` 表示在同样的置信度和区域约束下数量为 0。

组合操作为 ALL（并且）、ANY（或者）、NOT（取反），可嵌套。基础条件还支持数量比较（等于、不等于、大于、大于等于、小于、小于等于），每条条件可独立设置置信度。

| 用户意图 | 条件 |
| --- | --- |
| x、y、z 均出现，a、b 均缺失 | ALL(present(x), present(y), present(z), absent(a), absent(b)) |
| x 或 y 至少一类缺失 | ANY(absent(x), absent(y)) |
| x、y 都缺失 | ALL(absent(x), absent(y)) |
| x、y 至少一类出现，而 a 缺失 | ALL(ANY(present(x), present(y)), absent(a)) |
| 有人，但没有可见安全帽或未佩戴头部 | ALL(present(person), absent(helmet), absent(bare_head)) |

不存在于选定模型类别表中的名称属于配置错误；推理暂停、尚无结果、断流、推理失败与过期结果属于未知状态，均不得按“数量为零”触发缺失规则。规则阈值不得低于模型输出过滤阈值而声称仍能使用被过滤的检测框。

支持三种通用条件：类别出现/缺失与指定数量、两类目标的数量比较、逐个主体的空间关联。
“有人但整幅图没有帽子”与“至少一个人没有匹配到帽子”是两种不同条件。

### 两类数量比较

```json
{"compare_counts": {
  "left": {"class": "x", "min_confidence": 0.3},
  "right": {"class": "y", "min_confidence": 0.3},
  "op": ">"
}}
```

支持 `==、!=、>、>=、<、<=`。例如 x 检测到 2 个、y 检测到 1 个时，上述条件成立。
两类都按同一计数 ROI 筛选，置信度可分别设置。数量比较不判断空间对应关系。

### 逐个主体检查关联

```json
{"association": {
  "subject": {"class": "x", "min_confidence": 0.3},
  "object": {"class": "y", "min_confidence": 0.3},
  "relation": "center_inside",
  "state": "unmatched",
  "quantifier": "any",
  "one_to_one": true,
  "min_overlap": 0.5,
  "max_distance": 1
}}
```

类别来自用户的模型标签，没有固定业务类别。上述配置表示“至少一个 x 没有匹配到对应的 y”。
两个 x 只有一个对应的 y 时采集；即使 y 数量足够，但某个 x 的对应位置没有 y，也可采集。

- `relation=center_inside`：y 框中心位于 x 框内。
- `relation=overlap`：框交集面积占 y 框面积达到 `min_overlap`（大于 0、最多 1，默认 0.5）。
- `relation=near`：两框中心距离不超过 x 框对角线乘 `max_distance`（大于 0、最多 100，默认 1）。
- `state=unmatched/matched`：判断没有匹配到/匹配到了对应目标。
- `quantifier=any/all/count`：至少一个/全部/按数量判断的主体满足该状态。`count` 模式需要
  `"count":{"op":">=","value":2}` 等数量要求。没有有效主体时关联条件不成立，包括“全部”模式。
- 默认 `one_to_one=true`，每个 y 最多分配给一个 x，通过最大二分匹配避免贪心分配的假缺失。
  设置 false 允许同一个 y 为多个 x 提供关联。相同类别关联不会用一个框匹配它自己。
- ROI 只筛选关联主体 x；关联目标 y 来自同帧模型的全部有效输出，允许位于计数 ROI 外。
  推理 ROI 之外的目标不会凭空补出。关联只使用有效矩形框，两个类别的置信度分别过滤。

数量比较和关联条件均可放进 ALL、ANY、NOT 组合。不同关联条件各自匹配；例如两条“至少一个 x
缺少 y/z”的 AND，可能由不同 x 分别满足，并不表示同一个 x 同时缺少 y 和 z。
空间关联是模型检测框的几何判断，不证明真实佩戴/归属关系，也不判断头部是否可见。

## 配置入口与触发节奏

在 Web 侧边栏打开“数据集采集”，点击“新建采集任务”，选择采集通道、确认模型类别，再填写规则。无需更换通道业务逻辑或新建推理通道。同一任务的多组规则之间使用“或”，一帧命中多组规则只采集一次。

“抓图间隔”限制相邻采样的频率；“持续确认时间”要求条件连续成立后再触发。“每次刚满足时抓一次”按条件从不成立变为成立触发，仍遵守抓图间隔。过期、重复或无效推理结果不会重复触发采集。

图片由电脑接收程序保存到用户选择的目录，任务管理和当前存图统计均在 Web 页面查看。操作与部署说明见[电脑数据集采集](computer-dataset-collection.md)。
