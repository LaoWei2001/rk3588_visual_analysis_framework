# 大模型功能开发提示词模板

> 文档角色：面向执行阶段的大模型任务模板，不是项目总入口，也不替代源码核对和人工验收。使用前先看 [docs 文档总入口](README.md)。  
> 用途：让有本仓库读写权限的大模型按照当前 `rk3588_visual_analysis_framework` 的真实架构完成二次开发。选择模板、替换 `【】` 后整段发送即可。

## 30 秒上手

1. 从路由表选择最接近的模板。
2. 替换全部 `【...】`；不需要的项写“无”。
3. 有仓库权限的 Agent 直接读取文档和源码；普通网页版模型还需要附上模板中列出的文件内容。
4. 默认让模型只修改文件并做静态检查，不执行 Git、构建、安装、重启或部署；这些命令只需在收尾说明中提供，由你决定是否运行。

## 信息可信度顺序

先从 [docs 文档总入口](README.md) 判断任务边界，再选择对应模板。项目文档可能落后于代码；技术事实应按以下顺序判断：

1. 当前源码、头文件、前端序列化和后端路由；
2. `docs/skills/rk3588-src-modules/` 中的当前模块说明；
3. `docs/skills/*/SKILL.md` 和 references；
4. 课程大纲、当前 examples 和本提示词模板；
5. `docs/development_log.md` 中的历史说明和旧注释。

出现冲突时以源码为准，并在结果中指出冲突。不要因为示例里出现某个函数或字段，就假设当前代码仍然存在。

## 我要做什么 → 用哪个模板

| 需求 | 模板 |
|---|---|
| 单路画面“检测到 X 就做 Y” | A：新增通道逻辑 |
| 多路摄像头聚合、联动、周期巡检 | B：新增全局逻辑 |
| 修改或删除现有 channel/global logic | C：修改或删除逻辑 |
| 给 channel logic 增加网页参数 | D：新增可调参数 |
| Web 前端、FastAPI、服务、部署或 C++ 底层模块 | E：控制台、服务与底层模块 |
| “改了不生效”、报错或行为异常 | F：调试定位 |
| 给实时画面的通道增加自定义按钮/外部动作 | G：自定义按钮 |

拿不准时，先让模型盘点真实调用链再选模板。涉及 `logic_xxx` 的业务规则优先 A/C/D/G；其他问题使用 E/F。

## 写需求前需要明确的内容

| 维度 | 需要明确 |
|---|---|
| 目标 | label 的精确拼写、模型类型、是否依赖 track id/关键点/mask |
| 区域 | 全屏、任一 ROI、指定命名 ROI 或区域之间的关系 |
| 触发 | 存在、数量、持续时间、进入/离开、顺序、位置或姿态 |
| 状态 | 丢检宽限、复位条件、按目标还是按通道去重 |
| 画面 | 实时显示、告警图片、告警视频分别需要哪些叠加 |
| 告警 | 是否调用统一告警入口、事件字段、冷却/闩锁规则 |
| 投递 | 图片到服务器、图片到 Dify、视频到 Dify；由 Web 上报节点配置 |
| 验收 | 具体输入、预期画面、事件清单和日志表现 |

当前 logic 不负责保存服务器 URL、Dify 密钥或选择媒体。logic 只调用 `report_alarm()` 描述事件；Web 生成的 `report_policy` 决定投递目标、媒体、叠加、字段映射及录像参数。

# 模板 A：新增通道逻辑

````text
你是 rk3588_visual_analysis_framework 的 C++ 二次开发工程师。
任务：根据需求新增一个 channel logic，并完成当前项目所需接线。

## 权威上下文（动手前完整阅读）
- docs/README.md（任务边界与资料权威顺序）
- docs/skills/rk3588-src-modules/logic.md
- vision_analysis/src/logic/core/channel_logic.h
- vision_analysis/src/logic/core/logic_common.h
- vision_analysis/src/logic/README.md
- docs/skills/rk3588-channel-logic/references/channelcontext-api.md
- docs/skills/rk3588-channel-logic/references/logic-naming-and-registration.md
- 需要告警时再读：
  - docs/skills/rk3588-src-modules/alarm.md
  - docs/skills/rk3588-channel-logic/references/upload-and-wiring.md
  - vision_analysis/src/alarm/alarm_report.h
- 需要参数时再读：docs/skills/rk3588-channel-logic/references/adding-config-parameter.md
- 需要按钮时改用模板 G。

先检查 `vision_analysis/src/logic/modules/` 中的当前真实逻辑，选择最接近的实现参考。examples 只能辅助理解，必须先确认其 API 和字段仍存在。

## 需求
- 一句话：【ROI entrance 内 person 连续停留 3 秒后告警】
- C++ 入口函数/外部 logic ID（小写下划线，建议 logic_ 前缀）：【logic_person_dwell】
- Web 显示名：【人员停留告警】
- 模型和目标类别：【yolov8_det / person】
- 区域：【命名 ROI entrance】
- 触发条件：【连续命中 >= dwell_sec】
- 丢检宽限和复位条件：【丢检 1 秒内保留；离开 2 秒复位】
- 实时画面叠加：【命中框标红并显示状态】
- 告警媒体专用叠加：【与实时画面一致 / 另加文字 / 无】
- 是否产生告警事件：【是】
- 事件 type/message：【person_dwell / 人员停留超时】
- 事件字段 key/type/含义：【label:string、score:number、roi_name:string】
- 业务限频或闩锁：【一次进入只报一次，离开复位】
- Web 可调参数：【dwell_sec float 默认3，范围0.1-60】
- 其他验收条件：【无】

## 实施要求
1. 新建 vision_analysis/src/logic/modules/logic_person_dwell/logic.cpp：
   - include "logic/core/logic_common.h"；
   - 实现 static void logic_person_dwell(ChannelContext *ctx)；
   - 文件末尾用 REGISTER_LOGIC(logic_person_dwell); 自注册，函数名即外部 logic ID；
   - 不要把具体逻辑加入 channel_logic.cpp。
2. 新建同目录 logic.json：
   - 不手写 name，它由 REGISTER_LOGIC 的函数名自动生成；
   - 声明 label、parameters Schema；
   - 若会告警，report_fields 必须完整声明 C++ alarm_field 使用的 key，类型仅为 string/number/boolean/json；
   - 不要依赖旧 report 字段决定是否上报，是否投递由画布上报节点决定。
3. 告警只调用 report_alarm(ctx, type, message, fields)：
   - 不读取或新增 server_url、dify_api_url、dify_api_key、report_enable；
   - 不调用 alarm_uploader_enqueue/dify_uploader_enqueue；
   - 不直接发送 HTTP、不写 Redis、不自己编码媒体。
   - 没有有效 delivery 时该函数返回空字符串；业务代码不得把空事件 ID 当成功。
   - 自定义 fields 会写入 manifest，并可供 Dify 字段映射；当前服务器图片投递使用固定 JSON，不转发任意算法字段。
4. 普通模块参数只在 logic.json parameters.properties 声明，通过 ctx->param_*() 读取；选择正确的 preserve_state/reset_state/restart_required 策略，不增加 ChannelConfig/REG_C 中央字段。
5. 硬约束：
   - frame/results/ROI/draw 坐标统一为模型输入空间；源尺寸只用 ctx->src_width/src_height；
   - 跨帧状态放 *ctx->state，不用 static 或可变全局变量；
   - timestamp_ms 只做间隔，unix_ms/time_str 做日历时间；
   - 检查 ctx、state、frame、results、ROI 和配置是否可用；
   - logic 不做阻塞网络、长磁盘 IO、sleep 或无界循环；
   - DrawCommand target 要说明 DISPLAY/IMAGE/VIDEO 的选择；当前叠加图片复用 DISPLAY|IMAGE，叠加视频复用 DISPLAY|VIDEO。
6. 不修改任何设备/App 的运行 config.json。
7. 保留仓库中与本任务无关的已有改动。

## 验证与交付
- 只修改文件并做静态检查；不要执行 Git、构建、安装、重启或部署。
- 检查 JSON 合法、生成清单中的 logic ID 与 C++ 入口函数名一致、字段和 API 均真实存在。
- 最终说明修改文件、逻辑行为、Web 接线方式和验收步骤。
- 可列出由我手动运行的构建/安装命令：
  cd vision_analysis && ./build.sh dist && sudo ./install_app.sh dist
- 告警排查使用 alarm_store/<event_id>/manifest.json、Web 未上报告警页面和上传服务日志；不要给 Redis/dify_queue 命令。

只有会实质改变业务语义的歧义才先问；能从源码和现有约定确定的内容直接完成。
````

````text
6. 源码把 poll_interval_ms 下限限制为 10ms，并可能根据受监控通道 max_fps 自动缩短实际周期；实现和验收不能假定配置值就是最终 tick 周期。

8. 保留无关已有改动。
````

# 模板 F：调试或定位

````text
你是 rk3588_visual_analysis_framework 的问题定位工程师。先诊断根因；除非我明确要求修复，否则不要修改文件。

## 阅读

## 现象
- 最近改动：【】
- 期望：【】
- 实际：【】
- 原始报错/日志：【】
- 使用的 App、配置文件和通道：【】
- 已尝试：【】

## 定位要求
1. 用源码证据列出按概率排序的原因和最短验证路径，不凭印象下结论。
2. channel logic 重点检查：`REGISTER_LOGIC()` 入口函数名、生成 `logics.json.name` 和当前配置 `logic` 是否一致，label、ROI 名、模型坐标、state、冷却、当前配置文件。
````
