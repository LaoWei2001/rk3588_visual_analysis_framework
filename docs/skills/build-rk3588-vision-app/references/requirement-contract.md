## 先区分开发与运行环境

开始业务澄清前先记录：

- 当前运行大模型和工具的开发宿主；
- 最终部署视觉程序的目标系统/设备；本仓库向导先建议 RK3588 Linux，由用户用“是/否”简短确认；
- 可以执行 RKNN、RGA、真实视频、GPIO、systemd 和远端投递验收的位置；
- 当前宿主缺少、但实施或验收需要的工具。

启动器检测结果只是当前宿主的证据，不代表最终目标，也不证明某个硬件或服务可用。按环境拆分验证，
不能把 Windows/macOS/x86_64 上的静态检查或交叉编译写成 RK3588 实机通过。后两项优先由代理探测；
无法确认时直接记录为待实机验证，不要求用户预先填写硬件清单。

## 先判定运行层

通过 `develop_feature` 实施时，先增加一个硬判定：需求必须完全由通道/全局模块现有公共接口、
`logic.json` 和模块内 `report_templates/` 表达。需要修改引擎、配置解析、Web 源码、服务或测试时，合同
标记为“超出 Logic-only 白名单”并停止；不得请求扩大本次写入范围。

| 问题 | 通道 Logic | 全局 Logic | 引擎/Web |
|---|---:|---:|---:|
| 只依赖一路当帧结果 | 是 | 否 | 否 |
| 要求每个业务帧立即响应 | 是 | 通常否 | 否 |
| 依赖两路以上公开变量 | 上游发布 | 是 | 否 |
| 周期汇总、跨通道选择来源 | 否 | 是 | 否 |
| 新视频源、模型类型、公共 Context 字段 | 否 | 否 | 是 |
| 只改变远端字段、URL 或认证 | 否 | 否 | 投递契约/连接 |

同一需求可以拆为“通道发布稳定变量 + 全局组合判断 + 标准事件上报”。不要让全局模块强转另一个 Logic 的私有 `shared_ptr<void>`。

## 必须明确的业务语义

在可以从目标模块和需求直接确定时自行确认。下表是内部合同字段，不是逐项问卷；优先把相关字段合并为
一个具体推荐，让用户用“是”或“否 + 不同之处”确认。

| 维度 | 要明确的内容 |
|---|---|
| 目标 | 标签名、模型来源、置信度/跟踪确认要求 |
| 空输入 | 没有结果、通道离线、全局输入不足时跳过、清状态还是保持 |
| ROI | 任一区域、指定名称、区域并集，未配置 ROI 是否等同整帧 |
| 时间 | 连续时长、允许间断、使用 `dt_ms` 还是墙钟 |
| 多目标 | 任一、全部、计数阈值、按 `track_id` 分别维护 |
| 触发 | 上升沿、条件持续周期触发、按钮触发或每轮一次 |
| 复位 | 条件解除、冷却结束、Action、参数热更新或进程重启 |
| 去重 | 每轨迹、每事件类型、每通道、策略合并或永不合并 |
| 失败 | `report_event()` 被拒绝时是否保持闩锁、重试还是允许下帧再次尝试 |
| 观察 | 画面、公开 output、事件、GPIO、日志或 Web Action |

时间间隔使用单调时间：通道用 `ctx->timestamp_ms`/`dt_ms`，全局用 `gctx->timestamp_ms`/`dt_ms`。日历与上报时间使用 `unix_ms`。不要从单调时间换算日期。

## 上报合同

需要上报时，先写清：

1. `event_type`，并在 `logic.json.event_types` 声明；
2. `message` 的业务含义；
3. 每个动态字段的 key、类型、单位和来源；
4. `EventMergeMode::NEVER` 还是显式 `POLICY`；默认是 `NEVER`；
5. 是否需要 `annotated_image`、`raw_image`、`video` 或纯数据；
6. 全局事件的来源通道与视频来源通道；
7. 远端协议是复用/修改程序包模板，还是创建新 ID 的自定义模板；同 ID 时程序包模板优先，不能靠
   custom 文件覆盖；
8. 失败后的闩锁和重试语义。

`accepted()` 只表示本地持久化队列接受事件。远端成功由 `delivery_state.json`、上传服务日志和远端回执判断。

## 可安全采用的默认值

以下默认不会擅自改变业务边界：

- 不需要跨通道就选择通道 Logic；
- 普通模块参数使用 `preserve_state`，但改变状态机含义的阈值使用 `reset_state`；
- 跨帧状态只放 Context 的 `state`；
- 不需要合并就保持 `EventMergeMode::NEVER`；
- Action handler 只改快速运行时状态，依赖当前帧的工作交给紧随其后的 Logic；
- 未要求修改平台能力时，不改公共配置、Web、Adapter 或框架线程；
- 未要求硬件控制时，不引入 GPIO；
- 未给远端协议时，只完成标准事件，不虚构 URL、字段或返回判定。
- 通过 `develop_feature` 时，所有源文件改动只允许落在两个 Logic 模块根目录；其他改动没有默认例外。

标签名、ROI 名、持续/复位规则、重复报警语义、远端字段、媒体需求和全局视频来源不能静默默认；应先从
源码和现有配置提出明确推荐，再由用户一次性确认，而不是拆成多个问题。

## 开始实现前的输出

复杂任务先形成一份短合同：

```text
环境：开发宿主、部署目标、可用硬件、分层验收边界
写入：channel/global 模块白名单及是否完全可实现
运行层：channel / global / engine / web
输入：通道、模型、标签、ROI、公开 outputs
触发：布尔条件 + 时间条件 + 多目标规则
状态：字段、初始化、更新、复位
输出：绘制 / outputs / Action / GPIO
事件：type、fields、merge mode、媒体、失败语义
配置：参数 key、类型、默认值、范围、热重载策略
验证：静态校验、构建、测试、板端观察点
```

合同中的每个名词都应能映射到现有 API 或待新增的明确文件。映射不了的项先查源码，不得自行发明接口。
