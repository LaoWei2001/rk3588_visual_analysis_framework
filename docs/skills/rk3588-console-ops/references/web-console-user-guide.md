# Web 控制台用户手册

默认安装脚本把控制台部署到 `/opt/ai_apps/_console`，监听 `0.0.0.0:8080`。登录使用板端 Linux
系统账号密码；token 保存在浏览器 localStorage，后端 session 在内存中有效 8 小时，控制台重启后
原 session 也会失效。

## 页面地图

| 路径 | 页面 | 当前用途 |
|---|---|---|
| `/` | 程序管理 | 安装包、配置选择、启停、自启、编辑、日志、事件 |
| `/live-view` | 实时画面 | 当前唯一运行 App 的拼接视频、实时日志和 logic Actions |
| `/editor/:appName` | 配置编辑器 | 图形化生成 `assets/*.json` |
| `/logs/:appName` | 程序日志 | journald 跟随到 Web 的有界日志 tail |
| `/records/:appName` | 事件投递 | 本地 outbox、媒体、JSON、重试与删除 |
| `/services` | 系统服务 | OTA、统一上传及 GPIO 状态保持服务 |
| `/system-settings` | 系统设置 | 设备信息、性能、存储、网络、时区与定时重启 |
| `/recovery` | 故障恢复 | 系统、网络、程序恢复策略及运行记录 |
| `/camera-settings` | 摄像头配置 | 摄像头发现与连接配置 |
| `/video-capture` | 视频采集 | 视频录制到电脑 |
| `/dataset` | 数据集采集 | 采集任务、触发规则和电脑接收端 |
| `/terminal` | 终端命令行 | 单个前端实例最多打开 4 个独立板端登录 shell |
| `/login` | 登录 | Linux/PAM 凭据登录 |

普通 API 请求需要有效登录；Axios 使用 Bearer token，原生媒体与 WebSocket 使用 query token。
Action 与电脑采集接收端使用各自认证协议，具体边界见[开发文档](web-console-development.md#路由和鉴权)。

## 程序管理

程序卡片来自 `/opt/ai_apps/<App>/`。完整包通常含二进制、`assets/`、`logics.json`、
`report_templates/` 和 `services/`。

- “上传程序”接受 zip、tar.gz、tgz、tar；先校验并准备程序包，再停止受管视觉程序并替换。无效包不会触发停机。
- 系统只允许运行一个视觉 App；启动第二个会返回冲突，必须先停止当前 App。
- 启动前选择 `assets/` 下的 JSON 配置，然后点击“启动”。
- HDMI 是否显示由配置中的 `global.enable_display` 决定；Web 启动过程不会改写配置。
- “开机自启”记录程序和启动配置，由独立运行管理服务恢复视觉 App 和对应后台服务，不依赖 Web 启动。
- 红色“停止”按钮请求正常退出并等待引擎清理；页面会区分已确认正常退出、存储错误和无法确认完整清理。
  详见[程序停止说明](../../../operations/application-recovery.md#用户主动停止与退出结果)。
- 删除 App 前会停止进程。删除对话框可选择保留告警和运行数据，或连同 `.data/<App>` 一并删除。

Web 上传替换同名包时，`.data/<App>` 位于包外而保留；包内手工修改会随新包被替换。

## 配置编辑器

工具栏支持新建、打开 App 内配置、本地导入、导出、另存为和保存；保存目标必须是 `assets/`
直属的 `.json`。未保存修改在离开页面时会确认。

画布节点与配置关系：

| 节点 | 当前配置结果 |
|---|---|
| 视频流 | 一个 `channels[]` 项；支持 RTSP、文件和 USB 来源 |
| YOLO 推理 | 该通道的 `models[]`；同一通道可连接多个模型 |
| ROI 区域 | `channels[].roi_zones[]`；直接关联视频流 |
| 逻辑函数 | 可选的 `channels[].logic` 与 `logic_parameters` |
| 上报配置 | 通道或全局实例的 `report_policy/report_parameters` 中一条 delivery |
| 全局逻辑 | `global.global_logics[]`，输入通道来自画布连线 |

业务 ROI 绘制同时展示原始画面和固定 640×640 业务画布。配置保存归一化坐标，运行时映射到
业务坐标；例如 1920×1080 原图的 `(960,540)` 保存为 `(0.5,0.5)`，对应业务 `(320,320)`。
业务 ROI 不随模型输入分辨率改变；推理 ROI 是独立的模型取景范围，检测结果先映射回完整画面。
完整约定见[业务坐标](../../../reference/business-coordinates.md)。

没有 YOLO 节点时仍是正常视频通道：`infer_enable=false`、`models=[]`；直接连接 logic 可做传统 CV
或无推理业务，logic 收到空 results。没有 logic 时仍显示/推理/系统绘制，只是不运行自定义业务。

Logic 和参数选项来自 App 根 `logics.json`，不是前端硬编码。上报连接、接口模板和 OTA 参数从
“应用集成”弹窗管理。底部同时显示全局设置和将要保存的完整配置预览。拖动右侧配置栏的左边框可
调整配置栏宽度，拖动底部栏的上边框可调整底栏高度；浏览器会记住最后一次尺寸。

保存后，正在运行的 C++ 会监控当前配置。普通参数、ROI、模型、流和全局实例可走各自热重载；
有效通道数量或按 ID 排序后的 id/enable 拓扑，以及输出拓扑类变化会拒绝热更新并要求重启。仅重排
配置文件中通道项、但有效 ID 集合不变时，不会因此被判定为拓扑变化。详细边界见
[`rk3588-src-modules` 配置参考](../../rk3588-src-modules/references/configuration.md)。

## 应用集成与上报节点

在“应用集成”中先完成：

1. 新建 `http` 或 `dify_workflow` 连接；
2. 选择程序包模板，或创建绑定某个 logic/事件类型的接口契约；
3. 必要时设置 OTA 平台地址；
4. 保存。

回到画布，把“上报配置”连到会创建事件的通道/全局 logic，选择连接和契约。一个上报节点产生一
条 delivery；同一 logic 可接多个节点。模板决定媒体和字段映射，节点不应复制模板内部 mapping。
当前表单能设置图片叠加、视频前后时长、FPS 和合并窗口，但没有 `video_overlay` 选择器；新节点默认
`custom`，导入配置中的已有值会被保留。

编辑接口模板时，界面按“算法产生的数据 → 字段转换规则 → 最终发送请求”展示数据流。左侧
编辑基础信息和字段转换规则，右侧固定显示服务器最终收到的请求，两侧独立滚动；可拖动中间分隔线
调整预览宽度，也可直接复制 JSON。窄屏下编辑区和预览区改为上下排列。

上报节点中，开发者才需要的画布保存配置收进“高级诊断”折叠区。它会随画布修改实时刷新，并显示在完整
配置中的目标路径。该预览和保存按钮使用同一次 `graphToConfig()` 序列化结果，因此同一 logic 下多个上报节点
合并后的 `report_policy.deliveries`、`report_parameters` 和媒体策略都以最终写入值为准。“最终发送请求”则根据接口模板
把一条告警记录转换为实际 HTTP 请求，与画布保存配置不是一类内容。

“告警记录与发送”页默认以摘要形式展示算法字段和发送状态，不再要求用户直接阅读整份内部 JSON。媒体状态、
发送任务和系统时间戳等完整原始内容仅放在“高级诊断：查看完整原始数据”中。

## 实时画面

页面自动跟随当前唯一 `running` App，读取其 `run.config` 对应配置。正确预览必须满足：

- `global.enable_rtsp` 非 0；
- `global.rtsp_codec` 是 `h264` 或 `avc`；
- App 的 RTSP 服务实际可在配置端口/路径访问；
- 板端存在支持 RTSP/fMP4 的 `ffmpeg`；
- 浏览器支持 MSE/H264。

数据路径是板内 RTSP H264 → FFmpeg stream copy → fragmented MP4 → 浏览器 MSE，不重新编码。
同一 App 的多个观众共用封装进程，各有独立的接收队列，新观众不会替换其他观众。页面同时显示当前 App 日志和由
`logics.json` 声明的通道/全局 Action。拖动日志与视频之间的竖向边框可以调整右侧日志/功能栏宽度，
浏览器会单独记住实时画面的栏宽；页面变窄并切换成上下布局后不显示拖拽条。连接视频时显示的是
约 3 秒的纯 CSS 等待进度提示，并非网络下载百分比；它不参与拉流、缓冲或解码，浏览器真正开始
播放时会立即撤掉遮罩，不为展示进度额外延迟画面。

点击拼接画面中的任一小窗即可单独查看，再点击放大后的画面恢复多窗；没有通道下拉菜单或单独的返回按钮。
右上角“全屏”适用于这两种观看方式，操作全屏按钮不会切换拼接/单路视图。
键盘用户也可用 Tab 选中画面按钮，再按 Enter 切换。空白格和画面外的黑边不会选中通道。
文件视频的进度条仍操作原通道，点击或拖动进度条不会进入放大。

单独查看提供两种模式：

- “独立预览”：程序支持时默认使用独立通道流，直接按视频源的分辨率输出，无需设置清晰度；
  画面按窗口大小等比例显示，按需占用引擎预览编码资源，同一通道的观众共用编码流。
- “画面放大”：浏览器裁剪当前拼接流，不增加编码资源，也不能增加原小窗的图像细节。
  旧程序不支持独立预览时自动回退此模式。

这两种方式都不修改算法或持久配置，各观众选择独立。断流重连保留当前选择；切换应用、运行配置
或应用重启后恢复拼接视图。独立预览连接结束会释放通道租约；异常断线还有租约到期回收机制。

## 事件投递页

页面读取 `.data/<App>/event_store/` 中仍存在的事件，可查看事件字段、delivery 状态、原图/标注图/
视频，手动重试未成功 delivery，或删除单条/全部事件。

它不是历史报表：所有 delivery 成功后上传服务会删除事件目录，因此成功项会消失。删除操作也会
永久移除本地目录，远端是否留存由远端系统负责。

## 系统服务、设置和终端

- 系统服务页的应用服务包括 `ota_agent.service` 与 `unified_upload.service`，启动/重启前必须先运行
  含对应服务的视觉 App；独立的 `rk3588-gpio-restore.service` 负责 GPIO 状态保持。
- 应用服务“开机自启”由共享运行管理记录并编排；两个底层 unit 被 disable，避免自行绑定旧 App。
- 系统设置提供设备信息、性能与温控、数据存储、IPv4 网络、时区与每日重启。网络切换采用确认/超时
  回滚事务，结果未确认时不要同时从另一入口修改网络。设备诊断见[设备信息与取证](../../../operations/device-diagnostics.md)。
- “故障恢复”集中管理系统、网络与程序恢复，策略默认值和生效方式见[恢复说明](../../../operations/unattended-recovery.md)。
- 终端以当前登录的 Linux 用户身份启动 PTY 登录 shell，工作目录默认 `APPS_ROOT`。一个前端实例最多
  4 个窗格；后端每登录 token 最多 8 个、设备共 32 个会话。普通路由切换保留会话，意外断线支持
  300 秒恢复；主动关闭、注销或普通整页离开会通知关闭，通知未送达时由恢复窗口到期回收。

告警原图导出和电脑录像保存见[本地媒体保存](../../../guides/local-media-saving.md)，
数据集采集步骤见[电脑采集指南](../../../guides/dataset-collection.md)。
