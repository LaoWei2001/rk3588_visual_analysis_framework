# 性能显示优化与板端测试

测试日期：2026-10-05。设备：本项目所在 RK3588，aarch64，实际 RGA 设备可用。

## 结果

相对于本次优化前的实现（已修正 FPS 统计，但每帧保存完整背景、停帧时重新绘制完整画面），
本次改为只保存性能文字下方的 64 像素条带；关闭性能显示时不保存背景。
停帧更新只恢复、绘制、转换和提交此条带，数字不变则直接返回。

下表是三轮测试中「每轮平均耗时」的中位数，单位为每通道微秒：

| 场景 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 正常帧，性能显示关闭 | 4076.25 | 3934.47 |
| 正常帧，性能显示开启 | 4365.92 | 4194.16 |
| 停帧，性能数值未变化 | 1350.91 | 0.134894 |

开启性能显示时，正常绘制平均耗时下降约 3.9%。数值未变化的停帧刷新跳过了图像处理。
960×640 的单通道背景缓存由 1,843,200 字节降为 184,320 字节（减少 90%）；
四通道合计由约 7.37 MB 降为 0.74 MB。关闭性能显示时这项缓存为零。

优化后，开启与关闭性能显示的耗时差约 260 微秒/通道帧，仍然存在画字和条带保存开销，
不能据此承诺性能显示绝对零损失。计数器「记录一次 + 查询一次」的显式时间戳微基准
约 60 纳秒，无锁竞争；此数值不包含生产路径读取时钟的成本。

原始逐轮日志和汇总数据属于本地测试产物，不随仓库提交；可按下方命令重新运行测试。

## 测试方法与边界

- 直接调用生产代码 `display_commit_frame` 和 `display_refresh_channel_overlays`。
  使用实际 RGA 缩放、FreeType 文字、检测框绘制、BGR/RGB 转换和显示缓冲写入。
  各轮没有 RGA 失败或软件回退日志。
- 源图像为固定 1280×720 BGR 图像，画布为 1920×1280，四通道各 960×640，
  每通道五个检测框。四通道按顺序调用，OpenCV 线程数固定为 1。
  这与完整程序的并发调度、变化的图像内容和负载不同。
- 每种开关状态预热 20 轮，测量 240 轮，每轮提交四个通道帧。
  每个版本各测试三次，两种开关状态合计 5760 次帧提交。
  后两轮交替版本测试；未锁定系统 CPU 频率，结果存在调度、温度和频率波动。
- 推理 FPS 查询返回固定值 25，配置查询使用桩。该测试没有运行采集、NPU 推理、
  业务逻辑或 RTSP 编码，输出的 `fps_total` 只是这个绘制循环的吞吐。
- 尝试启动本地视频输入和 RTSP 客户端进行完整管线对比，但客户端连接收到 EOF，
  未进入有效媒体播放。因此没有使用空转 CPU 数据，也没有给出完整管线的 FPS 或 CPU 降幅。

## 复现当前实现

在项目根目录执行（需要板端 RGA、OpenCV FreeType 和原有构建依赖）：

```bash
cmake -S engine -B build/engine -DBUILD_PERFORMANCE_TESTS=ON -DBUILD_PERFORMANCE_BENCHMARKS=ON
cmake --build build/engine --target display_performance_benchmark display_metrics_tests performance_metrics_tests -j4
build/engine/display_performance_benchmark 240
cd build/engine
ctest --output-on-failure
```

微基准默认不参与常规构建或 CTest。它使用独立进程和内存画布，不修改业务配置。
`performance_metrics_regression` 验证窗口过期、恢复、并发计数、失败及覆盖发布口径；
`display_metrics_regression` 验证停帧刷新不虚增帧数、暂停归零、关闭后无残影、
条带缓存和红蓝交换路径。与跟踪、帧快照测试合计五项回归测试全部通过。
