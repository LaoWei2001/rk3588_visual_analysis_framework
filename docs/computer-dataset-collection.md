# 多路条件采集到电脑

Web 侧边栏的“数据集采集”用于建立附加采集任务，复用已经运行的通道推理，不替换通道的安全帽、人员入侵等业务 Logic，也不增加一次模型推理。条件解析、数量比较和目标关联由框架通用规则层提供。规则语义见[数据集采集条件](dataset-capture-rules.md)。

## 使用

1. 编译并安装新版视觉程序，重启程序；Web 后端也需要使用新版代码。
2. 在“数据集采集”选择视觉程序和通道。第一版每个被采集通道只支持一个启用的检测模型；多路通道可同时采集。只读取该通道实际推理出的类别，条件置信度不能低于模型输出阈值。
3. 点击“新建采集任务”后显示配置表单，选择尚未建立任务的通道，再设置采集条件、抓图间隔、每文件夹张数和停止条件。“最多保存几张”及“运行时长”为 0 时不限。点击“创建任务”后返回任务列表，每路独立点击“开始采集”。取消则关闭表单；未保存的修改在取消、切换通道或切换程序时提示确认。
4. Windows 10/11 64 位电脑选择“Windows 10/11 64 位（无需 Python）”，点击“下载通用 Windows EXE”，下载的是单个 `.exe`，无需解压、安装 Python 或安装其他依赖。Windows 浏览器默认选择此类型。Linux/macOS 选择 Python 版本，下载 ZIP 并解压，需要 Python 3.9+，无需 `pip` 安装依赖。
5. Windows 双击 EXE，首次填写设备控制台地址，并通过 Windows 文件夹选择器选择保存目录。以后打开会显示当前设备和保存目录：回车开始接收，`1` 修改设备地址，`2` 更换保存目录，`3` 同时修改，`0` 退出；无需登录或配对。修改设备地址时可沿用原目录，不同设备的图片和进度分别记录。取消目录选择会退出本次启动，原配置保留。程序在 EXE 旁生成同名 `.json`，只记录地址和目录，请放在可写目录。Linux/macOS 执行 `python3 dataset_receiver.py`，使用文件夹选择器或输入路径，下载包已填入设备地址。两个版本均可通过 `--url` 指定地址、`--output` 指定目录，`--choose-directory` 重新选择目录。EXE 还支持 `--start` 跳过启动菜单，直接使用保存的配置接收。
6. 保持电脑开机、不休眠，并保持接收程序运行。可以关闭浏览器、退出普通 Web 登录和断开 SSH。Web 可重新打开查看当前存图、累计保存、待传数量、接收目录和状态。

按 Ctrl+C 停止并退出，不需要再按回车；再次按 Ctrl+C 可立即终止。正常退出会主动通知设备离线并释放接收占用，通知最多等待 1 秒，设备不可达也不会卡住退出。Windows 关闭窗口时也会尝试发送通知，启动器短暂等待接收进程完成；网络请求卡住时，启动器仍在等待 3 秒后强制终止。相同设备和保存目录会记住本地接收编号。本地锁在进程结束后由系统释放，锁文件存在本身不表示还有程序在运行。强制结束时未写完的 `.jpg.part` 会在下次接收时重试，不提前确认图片。

Web 状态每 2 秒刷新。正常离线通知成功后，下一次刷新即显示“未连接”，更换电脑或保存目录无需等待旧租约。强制结束、断网、使用旧版接收器或通知失败时，仍在最后心跳 15 秒后判定离线，通信正常时页面约在最后心跳后 15～17 秒更新；不同接收端还需等待 30 秒占用超时。新版接收器连接旧后端时，离线接口失败不会影响退出。

通用 EXE 只需下载一次，可用于不同设备，在启动菜单或通过 `--url` 更换设备地址。一个接收程序会自动发现所连接设备所有视觉程序中新增或修改的采集任务，多路同时接收并按程序、通道分目录保存；新建任务、修改条件、暂停或继续采集均无需重新下载或重启 EXE。下载与连接配置始终直接显示。页面上方集中展示任务，下方宽版表单设置抓图条件和保存参数；小屏幕自动纵向排列。

配置表单仅在新建、查看或编辑任务时显示。已建立任务的通道只能从任务卡片编辑，避免新建时覆盖已有任务。运行中的任务显示“查看配置”，可点击“暂停并编辑”再修改；暂停任务点击“编辑配置”。保存修改成功后关闭表单，失败时保留输入并在表单内显示错误。程序在线时，删除前需暂停任务并接收完待传图片；待传图片未完成时也不能保存修改，界面显示具体原因。

视觉程序停止或采集连接不可用时可以直接删除任务，包括上次处于启用状态的任务，无需启动程序或先暂停。删除立即从 Web 配置移除并持久保存清理记录；连接恢复后，后台暂停旧任务、释放未传缓存并删除引擎记录，视觉程序/Web 后端重启不会重新恢复已删除任务。离线删除的确认框说明未传缓存会被清理，电脑已保存的图片始终保留。同一通道后来新建的任务不会被旧清理记录删除。此行为兼容现有引擎和 EXE，不要求重建或启动视觉程序。

电脑重启后运行原 EXE，沿用原保存目录即可。更换电脑时先正常退出原接收程序，通知成功即可在新电脑接收；异常退出或旧版程序需等待 30 秒占用超时。重复下载只获取同一个通用程序，不会影响正在运行的接收端。旧版本 EXE 在更新后的设备上也可继续使用，旧凭据不再检查。

接收地址默认浏览器的控制台地址，通过相同 HTTP/HTTPS 通路短请求轮询、下载和确认，不需要开放电脑入站端口或保持 SSH。企业跳板平台如果还有单独的网页认证、客户端证书或代理限制，需先确认接收程序能访问这些 Web 接口；浏览器能访问不代表其专用登录状态会自动共享给接收程序。接收失败会显示具体状态并重试。

接收程序允许直接填写 `192.168.2.41:8080`、`192.168.2.41` 或 `device:8080`，省略协议时自动使用 HTTP。HTTPS 设备填写完整 `https://...` 地址。首次输入、`--url` 参数和已有 JSON 配置均支持这种写法；内部保存完整地址，同一地址换写法不改变设备编号或已选择的保存目录。

## 保存与恢复

电脑目录示例（设备编号由控制台地址生成）：

```text
所选目录/
  <设备编号>/
    test_107/
      ch0/
        0_29/
        30_59/
      ch3/
        0_29/
  .dataset_receiver.sqlite
```

原图由条件命中的同帧源画面编码，保留源分辨率，不包含显示框和文字。第一版只传 JPG，不自动导出预测标签或采集侧 JSON。电脑 SQLite 只记录保存路径、接收编号和待确认状态，用于重启恢复和避免重复保存。每路单独编号，重启接续历史目录；改变每批张数时另起一个范围。删除任务不会删除电脑图片，新的任务会继续在该通道目录接续保存。

电脑先写 `.jpg.part`，刷新到磁盘并原子改名，再确认保存。累计保存只累计有效且首次收到的保存确认，用于采集数量上限；重复下载、重复确认或后端重启不会重复计数。断线自动重连；磁盘剩余空间低于 256MB 时暂停接收，保留待传图片。

Web 主计数“当前存图”来自所选电脑目录中本设备/程序/通道文件夹实际存在的 `.jpg`、`.jpeg` 文件，不按历史保存记录推算。删图或删除整个批次文件夹后会下降，全部删完显示 0；重命名后的 JPG 仍计数。同一通道旧任务留下的图片也属于当前存图，其他设备、程序、通道的图片分别统计；未写完的 `.jpg.part` 和符号链接不计入。

接收程序在独立后台线程通过流式目录遍历统计，每处理 256 个条目短暂让出 CPU，每轮完成后等待 5 秒再检查，通过现有轮询上报完整快照。统计不访问推理或显示管线，也不阻塞接收和保存；大目录需要更多时间，不承诺固定同步时限。Web 仍每 2 秒刷新。目录不可读时显示统计失败和未知数量，未完成首次统计或使用旧版接收程序时显示“—”，不会把累计保存冒充当前文件数。离线时注明显示上次统计；更换电脑或保存目录后重新统计。此功能需要更新前后端并替换新版接收程序，原地址和目录配置可继续使用。

手动删除图片不会减少累计保存，也不会自动恢复已经用完的采集额度。希望继续采集时，提高累计上限或重新建立任务。

RK3588 不保存采集图片文件。每路最多排队 8 张（含正在编码的图片），所有通道共享 64MB 原图/JPEG 队列预算；编码和传输仍有临时工作内存。后台编码原图队列最多两帧，满时跳过新样本，不卡住等待电脑下载。短暂断线可补传缓存；长期断线超出缓存、视觉程序重启或板端掉电时，未传图片无法恢复。Web 显示本次跳过数量；没有发生推理的时间不能按“零目标”抓图，也不能事后补采。

图片上限同时考虑已确认和待传图片，避免超额。时长从首次开始计算，暂停不延长结束时间；修改时长后，下次开始重新计算。配置和成功保存总数保存在板端 `.console_dataset.sqlite` 中，视觉程序/Web 后端重启后自动恢复。场景互锁暂停推理时，采集等待该通道恢复，不强行开启 NPU。

## 免登录接收

采集轮询、图片下载、保存确认和退出通知接口免登录，不需要接收凭据、配对或撤销操作。退出通知仅释放与当前接收编号匹配的占用，旧接收端迟到的通知不会断开其他接收端。任何能访问采集接口的电脑都能连接。建立、修改、开始、暂停、删除任务以及其他控制台功能仍需使用原有登录。关闭浏览器、退出 Web 登录或普通登录到期，不影响接收。

设备同时只接纳一个活跃接收端，避免两台电脑争抢同一份样本；多路图片在同一个接收程序中处理。图片保存确认仍由程序自动携带每张图片的校验信息，确保错误或重复确认不会增加保存数量；这不需要使用者配置。板端内部确认密钥持久化并缓存，不随下载或任务变化而更换，升级时兼容原来的待传图片确认。

接收端源码：`web_console/backend/resources/dataset_receiver.py`。板端 API：`web_console/backend/routers/dataset.py`；管理与持久化：`services/dataset_manager.py`。采集观察器：`engine/src/control/remote_dataset.cpp`，在业务 Logic 执行之前读取同帧推理结果，通过独立 `run.dataset.sock` 向 Web 提供图片，不占用逻辑动作控制 Socket。

代码职责、依赖方向和主项目接入点见 [采集功能代码边界](dataset-collection-architecture.md)。通用规则位于 `engine/src/dataset/`，框架观察器不依赖业务采集模块；Socket 通信与下载打包各自独立。

## Windows EXE 构建和部署

Windows EXE 在原有 Python 接收器外增加小型启动器，内置官方 Python Windows embeddable runtime，
无需查询电脑的 Python 安装或 PATH。采集、SQLite 保存状态、断线重连、重复图片处理和确认协议
使用同一份接收器代码。Windows 原生文件夹选择器不依赖 Tkinter 或 PowerShell。
运行时解压到电脑私有临时目录，结束后清理；图片和接收状态仍保存在用户选择的目录。

构建机需要 Go 1.23+ 和 Python 3；Linux/RK3588 或 Windows 均可构建 Windows 64 位程序。
这些要求只针对构建机，使用 EXE 的电脑不需要它们：

```bash
python3 tools/dataset_receiver/build_windows.py
# 离线构建：预先准备官方运行时 ZIP，脚本仍校验锁定的 SHA-256。
python3 tools/dataset_receiver/build_windows.py --runtime-zip /path/to/python-3.13.16-embed-amd64.zip
```

产物位于 `web_console/backend/resources/receiver/windows-amd64/`，包含
`dataset_receiver.exe`、`manifest.json` 及内置组件许可证。运行时版本锁定为 Python 3.13.16，
下载后校验 [Python 官方发布页](https://www.python.org/downloads/release/python-31316/) 的 SHA-256。
嵌入式运行时的用途见 [Python 官方说明](https://docs.python.org/3.13/using/windows.html#the-embeddable-package)。
部署控制台时必须一起携带整个产物目录；现有部署器和完整离线包会复制此目录。
本项目源码更新包也包含这些产物，不要求目标板重新安装 Go 构建 EXE。
修改接收器或启动器代码后重新构建；后端会拒绝分发与接收器源码不一致或校验失败的 EXE。
缺少 EXE 时明确报错，不影响当前接收程序或静默下载 Python 脚本。

Web 下载直接返回构建的通用 EXE，不再封装设备地址或接收凭据；首次运行只填写地址和目录。
Windows 上可执行以下诊断：

```powershell
.\dataset-receiver-windows-amd64.exe --check-runtime
.\dataset-receiver-windows-amd64.exe --choose-directory
.\dataset-receiver-windows-amd64.exe --start
.\dataset-receiver-windows-amd64.exe --url "192.168.2.41:8080" --output "D:\采集图片"
.\dataset-receiver-windows-amd64.exe --output "D:\采集图片"
.\dataset-receiver-windows-amd64.exe --licenses
```

`--check-runtime` 不连接设备，检查内置 SSL、SQLite、HTTP 和 Windows 文件锁组件。
EXE 体积约 14 MB，只在下载和电脑启动时有额外成本，不增加 RK3588 每帧推理或显示工作。

## 验证

```bash
cmake -S engine -B build/engine -DBUILD_DATASET_TESTS=ON
cmake --build build/engine -j4
(cd build/engine && ctest --output-on-failure -R 'dataset_rules_regression|remote_dataset_regression')
PYTHONPATH=web_console/backend python3 -m pytest -q web_console/backend/tests/test_remote_dataset.py
PYTHONPATH=web_console/backend python3 -m pytest -q web_console/backend/tests/test_receiver_package.py
```

回归测试使用真实 C++ 采集 Socket、HTTP 路由、JPEG 编码和电脑接收器，覆盖多路同时采集、原图、分文件夹、退出登录后接收、断线确认恢复、重复确认、队列上限和暂停。测试不代表已完成数天现场持续运行验收。

EXE 在 Linux/RK3588 上完成交叉构建，核验 PE32+ x86-64 格式、官方运行时完整性和校验值。
启动器测试覆盖旧配置兼容、设备地址校验、中文配置、配置更新、启动菜单编辑设备/目录、取消不保存、显式参数跳过菜单和运行时解压；后端测试覆盖通用单文件下载、免登录接收、
源码更新后拒绝旧二进制、缺失或损坏的 EXE 不影响当前连接、旧图片确认兼容及控制台仍需登录。存图测试覆盖实际文件删除、重命名、分目录统计、临时文件与链接排除、统计阻塞不影响接收和退出、未知/错误状态、接收端切换，以及通过真实 HTTP 同步删图后的数量且不改变累计上限。退出测试通过真实 HTTP 验证 Ctrl+C/SIGTERM 主动离线、立即更换接收端、旧接收端不能释放新接收端占用，以及离线通知失败/阻塞仍按时退出。Windows 原生启动和文件夹对话框
尚需在实际 Windows 电脑执行 `--check-runtime` 并进行采集验收。退出回归覆盖正常 Ctrl+C、第二次 Ctrl+C、网络阻塞时强制结束和本地锁释放；Windows 控制台信号转发和 Job Object 子进程清理测试已提供，但需 Windows 实机执行，Linux 上仅验证交叉编译。
