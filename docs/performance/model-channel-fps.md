# 四类模型多路并发：完整视频管线实测

测试日期：**2026-11-13**。在同一台 RK3588 上，分别运行 YOLOv8 检测、YOLOv8 Pose、YOLOv5 Seg 和 YOLO26 Depth，覆盖 **1 / 3 / 6 / 9 / 12 / 15 路**。每组同时启用独立视频解码、RKNN 推理、SORT、本地拼接显示、硬件 RTSP 输出和本机 FFmpeg 播放。

[项目首页](../../README.md#性能与验证) · [性能文档](README.md)

## 实测摘要

- 四类模型采用相同的路数矩阵和运行配置，两轮按正、反顺序执行，共完成 **48 / 48 组正式测量**。
- **最高成功推理总吞吐：186.45 FPS**，对应 YOLOv8 检测、9 路；平均每路 20.72 FPS。
- **最高结果发布总吞吐：183.84 FPS**，对应 YOLOv8 检测、9 路；平均每路 20.43 FPS。
- 15 路场景逐通道持续推理和发布的运行组数：**8 / 8**；RTSP 播放持续推进的运行组数：**48 / 48**。
- 退出结果：**48 / 48 组完成正常清理**；正式采样窗口的推理失败任务合计 0 次。

## 统计方法

1. 为四种模型分别构建 1、3、6、9、12、15 路配置，两轮采用正、反顺序。
2. 每组等待所有通道就绪，再预热 10 秒，采样 30 秒；15 路深度采样 60 秒。采样期间保持本地显示和 RTSP 播放运行。
3. 仅纳入位于采样区间内的完整 `[Perf]` 窗口，保留每路原始窗口时长、完成数、发布数和失败数。
4. 对同一模型、同一路数、同一通道，将两轮的原始计数与有效窗口时长分别累加，再计算 FPS。
5. 总 FPS 为所有通道 FPS 之和，平均每路 FPS 为总 FPS 除以通道数。最终表格统一保留两位小数。

对通道 `c`：

```text
有效秒数[c] = 两轮完整窗口的 window 之和
成功推理 FPS[c] = 两轮 completed 之和 / 有效秒数[c]
结果发布 FPS[c] = 两轮 published 之和 / 有效秒数[c]
总 FPS = 各通道 FPS 之和
平均每路 FPS = 总 FPS / 并发通道数
```

`completed` 记录成功完成的推理任务，`published` 记录成功写入最新结果槽的任务。一次任务包含该通道模型的输入准备、RKNN 执行和后处理；本轮每通道配置一个模型。RTSP 播放 FPS 使用 FFmpeg 的解码帧计数单独记录，反映拼接视频的输出节拍。

## 采样时长

15 路 YOLO26 Depth 的首个 30 秒采样区间中，通道 7 获得 3 个完整 Perf 窗口，采样器按每路至少 4 个完整窗口的标准结束该次记录。该次运行的应用、显示和 RTSP 正常推进，引擎完成正常退出清理。

正式矩阵将 **15 路 YOLO26 Depth 的两轮采样时间统一设为 60 秒**，为该并发规模收集充分的完整窗口。其他场景采用 30 秒，预热均为 10 秒；FPS 按各路实际完整窗口秒数计算。

## 复验办法

1. 按[构建指南](../guides/project-guide.md#3-板端调试构建)生成 `vision_analysis`，复验本轮条件时使用上述提交和 `-O3` 参数；准备表中四份权重、对应标签和 `1112.mp4`。
2. 在本机独立测试目录中，按[配置说明](../guides/project-guide.md#配置与坐标)为每种模型创建 1、3、6、9、12、15 路配置。每路分配独立通道 ID，启用推理并配置一个模型，将输入设为循环文件源，资源路径指向本机文件。
3. 使用上表的 worker、队列、限帧与 NPU 配置，开启 SORT、1280×720 GTK 拼接显示和 H.264 MPP RTSP 输出，关闭自定义 Logic 和事件。连接 DSI 屏，逐组运行 `vision_analysis <配置文件>`，为每组设置独立的 `RK_SHUTDOWN_STATUS_FILE` 路径并保存引擎日志。
4. RTSP 就绪后启动本机 FFmpeg 客户端，保持解码播放，并通过 `frame=` 计数核对播放持续推进：

```bash
ffmpeg -nostdin -hide_banner -loglevel error \
  -progress pipe:1 \
  -rtsp_transport tcp -i rtsp://127.0.0.1:18554/live \
  -an -vsync 0 -enc_time_base -1 -f null -
```

5. 每组等待所有通道就绪后预热 10 秒，采样 30 秒；15 路深度采样 60 秒。记录采样起止时间，按前述公式汇总完整 `[Perf]` 窗口。
6. 采样结束后向引擎发送 `SIGINT`，等待进程退出并检查完整清理记录，再结束 FFmpeg 客户端、开始下一组。按 4 模型 × 6 路数完成两轮正反序矩阵。
7. 对照每路推理与发布 FPS、整体吞吐、RTSP 连续播放状态和正常退出结果，记录复验日期及实际运行参数。
