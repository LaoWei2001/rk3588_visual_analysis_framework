# 行车静止安全帽检测

在 Web 配置画布中选中 `logic_crane_helmet`，通过“安全帽告警判断方式”选择：

- **检测到未戴帽头部才告警**（`bare_head`）：装卸区域内的人员匹配到足够置信度的未戴帽头部，才计为违规。只看见腿、头部被遮挡，或没有检测到头部时，计为“待判断”，不产生新的违规。需要模型包含未戴帽头部类别。
- **裸头优先与人员宽高过滤（综合模式）**（`missing_helmet`，默认）：匹配到裸头的人员不受大小阈值限制，计为违规；没有匹配到裸头或安全帽时，只有人员框宽度达到 `person_min_width` 且高度达到 `person_min_height` 才计为违规，任一尺寸不足均计为“待判断”。仍兼容只包含 `person`、`helmet` 的两类模型。

“未戴帽头部标签”默认 `bare_head`，须与模型标签表一致，也可填多个逗号分隔的名称，例如 `bore_head,bare_head`。人员和头部均使用各自的最低置信度。裸头框中心必须位于同帧人员框内；遇到重叠人框，只匹配覆盖头部最多、面积更小的一个人员框。同一人员的多个头部检测不会重复计数。

宽、高阈值使用固定 **640×640 业务画布**中的水平宽度和垂直高度，与原始视频或 RKNN 输入尺寸无关，不将长短边排序。默认均为 `40` 像素，范围为 0～640。宽、高必须同时达标，等于阈值仍参与判断；某一项设为 0 仅关闭该方向的过滤，两项均为 0 关闭大小过滤。例如默认阈值下，20×100 和 100×20 的框即使面积超过1600，仍分别因宽度、高度不足被过滤，40×40 则达标。人员不会在匹配裸头前因尺寸小被丢弃。

两个阈值可以在 Web 中独立保存，也可使用视频画面的“切换安全帽参数 / 当前参数 ±”分别临时调整，每次增减 1 像素；临时调整在下次启动恢复保存值。旧参数 `person_min_area` 已移除，当前配置迁移为 `person_min_width=40`、`person_min_height=40`，不再进行面积判断。

匹配优先级为：**同帧裸头证据 → 匹配到安全帽 → 缺帽分支的宽高判断**。同一人员同时出现裸头和安全帽检测时，裸头优先；其他人员或不同帧的裸头不能绕过该人员的宽高过滤。非有限置信度和零/负尺寸框不参与判断。

两种模式都沿用原来的人员脚点进入 `loading_zone` 的区域规则、违规确认时间和告警解除时间。切换模式或改变任一尺寸阈值会重置告警和计时；已经确认的告警在证据消失后仍需经过解除时间才清除。红框表示违规候选，绿框表示匹配到安全帽，灰框表示待判断。画面分别显示宽、高阈值、当前人员最大宽度、最大高度以及小框待判断人数；两个最大值分别统计，可能来自不同人员。

模块继续发布 `helmet_alarm`、`helmet_person_count`、`unhelmeted_count`，并增加 `helmet_unknown_count`。人员入侵模块与全局控制器的场景互锁、告警生成和输出控制逻辑不变。

## 后续鲁棒性改进方向

以下是根据当前实现提出的后续改进，本次未改变这些策略：

- 按人员 `track_id` 分别累计确认/解除时间，允许小范围的漏检容忍，避免不同人员交替出现拼出一次连续违规；当前确认闩锁按通道“是否存在违规人员”累计。
- 安全帽采用同帧、一对一的人员头部关联，减少邻人的帽框、手拿帽子或任意一像素相交导致的漏报。俯视相机应按现场头部位置确定几何规则，不能一律用人框画面上方代替头部位置。
- 远近区域分别标定宽高阈值，或结合人员轨迹稳定后的尺寸统计，减少框宽高在阈值附近来回抖动的影响。裸头分支始终不受大小过滤。
- 利用真实误报/漏报片段回放评估，分别统计远处小人、只露腿、多人遮挡、手拿帽子、灯光切换和画面边缘；按类别标定模型与 Logic 两层置信度。
- 遮挡频繁时可在同一现场视频上比较现有 SORT 与 ByteTrack 的低分框关联方案，再决定跟踪配置；参考 [ByteTrack 原论文](https://arxiv.org/abs/2110.06864)。
