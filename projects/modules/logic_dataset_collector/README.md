# 条件式数据采集通道

在 Web 的通道逻辑节点选择“条件式数据采集”，打开“启用抓图”。主界面每行只填写类别和选择“检测到/没检测到”，再选择“全部满足/任一满足”；下方实时显示抓图条件。填写板端保存文件夹、抓图间隔和张数上限即可。该通道只启用一个检测模型。

数量、置信度及复杂嵌套规则在“更多条件设置”中编辑；ROI、确认时间、容量和附加文件等在“高级设置”中调整。已有规则的结构和参数完整保留，不会因折叠或切换简洁界面而重置。高级条件也使用“检测到 / 没检测到 / 按指定数量判断”的表达，置信度以百分比填写（30 表示 0.3），内部配置仍保存 0～1 的原值。组合方式用完整句子说明，嵌套与反向判断单独折叠；条件组名称只用于备注，不决定判断逻辑。

- “出现”：类别数量至少 1；“未检测到”：类别数量等于 0。
- “x 或 y 未检测到”：任一满足组，内含 x 数量等于 0、y 数量等于 0。
- “x 和 y 都未检测到”：全部满足组，内含同样两项。
- “x/y/z 均出现而 a/b 均缺失”：全部满足组，加入三项至少 1、两项等于 0。
- 组可以嵌套，可以取反，每项置信度和数量独立配置。

复用同帧推理结果；停推理、旧帧、未知类别、类别被过滤、无效 ROI 均不按零目标触发。每帧最多保存一份原图，附所有达到持续确认/采样间隔的规则。采样间隔为全通道共享，持续确认与进入触发状态为每条规则独立。

原图保留源分辨率，不包含检测框和显示文字。JPEG 编码及存盘在最多两帧、64 MB 的后台队列中进行。队列满则跳过，不阻塞等待。达到本次数量上限停止采集；通道保存目录容量包含历史文件。容量/剩余空间不足时保留已有图片，在 RK3588 上备份并清理目录后可继续采集。修改任一采集参数会重置通道逻辑状态及本次数量，历史样本保留。

图片直接保存在 RK3588 文件夹中。通道参数“RK3588图片保存目录”可填写绝对路径，例如 `/userdata/my_dataset`；留空默认 `/userdata/rk3588_dataset_samples/<程序名>`。各通道放在 `ch0`、`ch1` 等子目录中。

默认仅保存 `<时间与会话编号>_ch<通道号>_f<帧号>.jpg` 原图，不创建单独的样本目录。没有专用管理页面、采集按钮或样本 HTTP API；规则仍在原有通道逻辑节点中配置。

可选打开“保存采集命中信息”，生成同名 `.json`；可选打开“保存YOLO候选标注”，生成同名 `.txt` 和 `.labels.txt`（类别表）。两个开关默认关闭。文件可直接通过 SSH/SFTP 在板端查看或取走，不创建告警记录、不上传服务器。原有版本已保存的文件保留，不自动搬移或删除。

**模型预测不是人工标签**：候选标注必须复核，特别需要补上被模型漏检的目标。这些规则按画面或 ROI 内类别数量判断，不执行人员与帽子的逐人关联。

详细配置与验证说明：`docs/conditional-dataset-collection.md`。
