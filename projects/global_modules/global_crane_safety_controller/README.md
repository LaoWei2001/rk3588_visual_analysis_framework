# 行车安全全局控制器

该逻辑只负责跨通道状态组合、事件创建以及现场硬件输出，不执行图像推理。

- 通道 0：`logic_crane_motion` 发布行车运动状态。
- 通道 1：`logic_crane_hook` 发布吊钩越界状态。
- 通道 2：`logic_crane_helmet` 发布静止场景安全帽违规状态。
- 通道 3：`logic_crane_intrusion` 发布运动场景人员入侵状态。
- 全局控制器：运动时吸合投影灯继电器；三类当前有效违规取或后控制喇叭。

吊钩告警始终参与喇叭控制。人员入侵仅在运动状态生效，安全帽违规仅在静止状态生效。灯光状态切换后会等待 `lamp_settle_sec`，这段时间不启用两类人员告警。

默认引脚与仓库示例一致：喇叭 `GPIO6_A0`，投影灯继电器 `GPIO6_A2`，高电平有效。`hardware_enabled` 默认为关闭，完成 ROI 和阈值调整后再开启。

## Web 画布连接

1. 新建 4 个视频流节点，全部填写同一个摄像头地址，通道 ID 依次为 0、1、2、3。
2. 通道 0 不连接模型，视频流直接连接 `行车运动帧差检测` Logic。
3. 通道 1 依次连接吊钩模型和 `行车吊钩安全圆检测` Logic，在 Logic 中填写吊钩类别编号。
4. 通道 2 依次连接只含“人”和“安全帽”两类标签的模型与 `行车静止安全帽检测` Logic；在该视频流上添加 ROI 节点并创建 `loading_zone` 区域。
5. 通道 3 依次连接人员模型和 `行车运动投影区域入侵` Logic；在该视频流上添加 ROI 节点并创建 `projection_zone` 区域。
6. 添加 `行车安全全局控制器`，把 4 个通道 Logic 的 `global-out` 全部连接到全局节点的 `global-in`。
7. 全局节点通道参数保持 0、1、2、3，轮询周期建议 100 ms。调试时关闭硬件输出，确认阈值与区域后再打开。

若需要把三类事件保存到本地告警箱或投递到服务器，从全局节点的 `report-out` 连接上报节点，并选择 `JNU 行车安全拼接图片告警` 模板。全局节点保持四路输入连线时，标注图和原始图均按全局画布布局拼接。只需要现场声光告警时可以不连接上报节点。

## Web 按钮

四个通道都提供核心参数按钮。运动、安全帽和入侵通道使用“切换参数 / 当前参数 - / 当前参数 +”调整；吊钩通道提供安全圆半径增减和时间阈值切换增减。所有核心参数、实时检测值和实时累计时间始终同时显示在对应视频窗口中；切换按钮只改变增减按钮的操作目标，并将该项用黄色高亮，不会隐藏其他参数，也不显示“正在设置”文字。时间参数每次变化 0.3 秒，按钮修改仅作用于当前运行实例，应用重启后恢复画布参数值。运动通道不再划分网格，直接逐像素比较相邻帧；超过灰度帧差阈值的有效变化像素会在预览中以半透明橙色显示。

全局节点提供当前告警消音、喇叭测试开关、投影灯测试开关、紧急关闭现场输出、恢复自动控制五个按钮。两个测试按钮都是保持式翻转：按一次开启并一直保持，再按一次关闭，不再自动超时恢复。紧急关闭会持续锁定两个输出，直到点击恢复自动控制；消音只针对当前一轮违规，全部有效违规解除后自动重新布防。

## 吊钩告警周期

吊钩连续位于安全圆外达到 `confirm_sec` 后进入一次告警周期，全局控制器只在该周期的上升沿创建一次事件。告警周期内即使吊钩在圆边界附近频繁出入，喇叭仍保持开启，也不会重复创建图片事件。只有吊钩重新可见并连续位于安全圆内达到 `clear_sec`，告警周期才结束、喇叭关闭并重新允许下一次上报。告警期间吊钩丢失不会被当作安全解除。

四个通道顶部状态文字均保留“深褐色重影/外描边 + 高亮前景字”效果。所有业务逻辑统一调用 `draw_text`，由 `shadow_enabled` 参数决定是否启用重影。底层为每个渲染线程建立独立 FreeType 实例、Unicode 单字形缓存和有界整行 LRU：稳定文本按整行复用，包含实时数字的变化文本由已缓存字形拼装，不再每帧重新栅格化整行或挤掉固定文本。字形值统一为 0/255，后续帧仅在实际包围框内进行掩膜着色；整行缓存设有 96 项、8 MiB 的线程级上限。窗口时间统一简写为“累计值/配置值”，吊钩丢失计时达到配置值后停止增长。

传统视觉逻辑由框架底层的单槽最新帧 worker 异步执行，解码回调只传递稳定帧引用；算法跟不上时覆盖旧 pending 帧，不累积延迟，也不阻塞同源其他通道进入 NPU。该调度属于公共管线能力，后续新增非推理逻辑无需单独改造。
