# GPIO 命令行控制工具

本目录提供 GPIO 诊断工具，安装后的工具名为
`rk3588-gpioctl`。它默认控制 `GPIO6_A0`，也可以通过 `--pin` 操作其他符合
`GPIOx_Yz` 命名规则的引脚。独立的 GPIO 电平保持服务开启时，每次成功设置输出后，
期望电平都会保存到 `/var/lib/rk3588-gpio/`；服务关闭时只改变当前电平，不保存。

安装服务后，测试程序通过始终运行的 `rk3588-gpio-control.service` 设置GPIO。后台进程会
持续持有输出线，因此命令返回后高/低电平仍然保持，不会因测试程序退出而变回硬件默认值。
这项实时控制能力不受“GPIO电平保持服务”开关影响。

输出电平、运行记录和开机保存值由后台在同一个串行请求内统一更新；命令行工具、视觉主程序
和 `vision_analysis/tests/test_gpio` 不再分别竞争写 `.state` 文件。已有命令语法和视觉业务
GPIO API 均不变，二次开发代码无需增加参数或初始化步骤。

## 构建与服务安装

```bash
./build.sh
```

正常部署时，在项目根目录执行 `sudo ./setup/install.sh online`，不需要再进入
`service/gpio_state/`。本目录的 `build.sh` 只用于单独开发和测试；首次安装会
启用 `rk3588-gpio-restore.service`；再次安装会保留网页中已有的开启/关闭状态。服务在
系统初始化和声音服务之前恢复所有已保存的 GPIO 输出。

## 使用

```bash
# 列出当前板卡全部 GPIO，并显示占用状态
./build/rk3588-gpioctl list

# 只列出空闲候选项和已经由本框架控制的 GPIO
./build/rk3588-gpioctl list --available

# 只查看指定 gpiochip，例如本板 PCA9555 所在的 gpiochip6
./build/rk3588-gpioctl list --chip 6

# GPIO6_A0 切换为输出低电平（保持服务开启时同时保存）
sudo ./build/rk3588-gpioctl output 0

# GPIO6_A0 切换为输出高电平（命令退出后仍保持）
sudo ./build/rk3588-gpioctl output 1

# 查询框架正在保持的输出值和持久化保存值；不会改变引脚
sudo ./build/rk3588-gpioctl get

# 读取一个已经处于输入方向的空闲端口；只返回外部输入的逻辑 0/1
sudo ./build/rk3588-gpioctl --pin GPIO6_B3 read

# 将引脚切换为输入，并由新版 GPIO 后台持续保持该方向
sudo ./build/rk3588-gpioctl --pin GPIO6_B3 input

# 将引脚切换为输出；必须明确给出初始电平，避免出现意外脉冲
sudo ./build/rk3588-gpioctl --pin GPIO6_B3 output 0

# 指定其他引脚并切换为输出低电平
sudo ./build/rk3588-gpioctl --pin GPIO6_A2 output 0

# 手动模拟一次开机恢复
sudo ./build/rk3588-gpioctl restore
```

构建产物统一使用 `./build/rk3588-gpioctl`。

`get` 和 `read` 有意采用不同语义：

- `get` 只查询实时控制服务正在保持的输出值，以及状态目录中已有的持久化值。查询过程
  不会重新施加输出，也不会把线路切换成输入。没有输出状态时会提示用户改用 `read`。
- `read` 只读取外部输入电平。目标必须已经是空闲输入；如果它正由本框架保持为输出、
  仍处于输出方向或被其他驱动占用，命令会拒绝操作，不会偷偷改变方向。

`input` 会把线路切换为输入，新版实时控制后台会持续持有该方向，随后可反复使用
`read` 采样。若 GPIO 电平保持服务已开启，它还会删除该引脚以前保存的输出值，防止重启时
又恢复成输出；保持服务关闭时则遵守原有规则，不修改旧保存值。`output` 必须同时给出
`0/1`（也可写 `low/high`），保持服务开启时会保存输出值。内核或其他驱动已经占用的线路不会
被强行抢占。

只升级本目录程序、尚未升级 GPIO 后台时，空闲线路仍可直接切成输入，但命令退出后不会由
后台持续占用；由旧后台保持为输出的线路无法原地切换，需先安装新版后台。运行中的输入方向
记录在 `/run/rk3588-gpio-control/*.input`，后台服务重启时会恢复；整机重启后硬件通常回到
输入默认态，而工具通过清除旧输出保存值保证不会主动把它恢复成输出。

新版实时控制后台提供独立的 `STATUS/READ` 协议；命令行工具同时兼容已安装的旧后台：
旧后台不认识新协议时，`get` 会读取它维护的 `/run/rk3588-gpio-control/*.level` 运行记录，
`read` 会先确认线路确实为空闲输入再由本地读取。因此只运行本目录的 `build.sh` 也可以
使用新命令；统一部署时仍建议通过项目安装入口同时升级命令行和后台。

`list` 是无扰动扫描，不会申请线路或改变电平。每一行会显示动态生成的 `GPIOX_YZ`、
offset、电源域、高电平电压、设备树线路名称、当前方向、占用者，以及以下状态：

- `可控-空闲`：当前没有内核或进程占用，是可以进一步核对的候选GPIO。
- `可控-本框架`：已经由实时GPIO后台持有，可继续用本工具或视觉程序设置。
- `禁止-已占用`：由电源、复位、USB、扬声器或其他内核功能使用，不应进行电平测试。

电压列的含义：

- `约1.8V（固定）`：该 RK3588 IO 电源域只允许 1.8V，输出高电平约为 1.8V。
- `1.8V或3.3V*`：该电源域在芯片层面支持 1.8V 或 3.3V，实际值由板级供电连接决定，
  不能把它理解成“当前一定是 3.3V”。
- `约x.xxV（设备树）`：程序从该 GPIO 控制器的 `*-supply` 关系找到了固定稳压器；
  这是设备树标称配置值，不是对引脚的实测值。
- `供电未描述*`：程序已经识别控制器，但设备树没有提供它的供电关系；如果它是
  PCA9555 等扩展芯片，高电平仍然跟随扩展芯片的供电，并不是让用户给 GPIO 外接电源。
- `需查RK806电路*`：线路来自电源管理芯片 RK806，不能套用 RK3588 VCCIO 电压。
- `x.xx-y.yyV范围*`、`电压未知*`：找到了供电关系，但设备树只给出范围或没有给出电压。

本工具不再根据 `gpiochip` 编号或某个固定 I²C 地址猜控制器。它从 `/dev/gpiochipN`
对应的 sysfs 设备开始，动态读取设备树 `compatible`，无法取得 `compatible` 时再沿父设备
查找实际驱动；如存在 `vcc-supply` 等属性，还会解析其 regulator 节点和电压范围。列表
最后一列会显示识别依据，例如本板显示
`gpiochip6/3-0021/nxp,pca9555`，证明它来自 PCA9555，而不是所谓“RK3588 GPIO6”。换板后
即使 PCA9555 的总线、地址或 `gpiochip` 编号变化，也仍按 `compatible` 识别。

RK3588 原生 `gpio0`～`gpio4` 先通过整机 `compatible=rockchip,rk3588` 和控制器标签共同
确认，再按芯片固定管脚表映射 PMUIO/VCCIO。其他 SoC 不会误套 RK3588 电源域表；要显示
其他 SoC 内部 GPIO 的精确电源域，需要再为该 SoC 增加对应的芯片管脚映射。

`list` 会在全部结果的底部逐项解释上述文字。带 `*` 的电压之所以不显示一个猜测值，
是因为当前运行设备树没有公开这些板级 IO
电源轨；错误地把 1.8V IO 当成 3.3V IO 可能损坏芯片。输出高电平还会随负载产生少量
压降，因此精确电压以实测为准。

Linux GPIO 接口可以读取逻辑值 `0/1`，但逻辑 `1` 只表示高电平，不会返回实际电压值。
即使系统能够读取某个稳压器的设定值，它也不是对 GPIO 引脚电压的实测。本机设备树没有
提供 VCCIO 和 PCA9555 供电轨的对应关系，因此带 `*` 的项目需要查原理图或外接万用表；
若产品以后必须由软件获得实测电压，需要在硬件上将相应电源轨接入 ADC 或电压监测芯片。

注意：`可控-空闲`只表示软件层面没有占用，不能证明引脚已经引出，也不能证明翻转它在
电气上安全。切换板卡后应重新运行`list`，根据输出中的`gpiochip/标签`和`线路名称`与该板
原理图交叉确认，再对单个引脚执行 `output 0/1`；程序不会冒险自动翻转所有空闲 GPIO。

`toggle` 和不带参数自动翻转的旧行为已经移除。不带命令运行只显示帮助，不会读取、切换
或输出任何 GPIO。输出控制必须明确使用 `output 0/1`。

视觉主程序的 `src/gpio/gpio.cpp` 使用同一个独立服务开关和状态目录。视觉程序不能启停
保持服务；服务开启时成功输出会更新状态，服务关闭时则只进行实时控制。
