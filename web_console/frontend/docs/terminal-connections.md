# 网页终端连接与恢复

终端使用独立 PTY shell。切换页面保留会话；关闭分屏、退出登录或正常离开网页时显式回收。

## 断线处理

- 新前端使用 WebSocket 协议版本 2。每个分屏生成随机会话 ID，后端将其绑定到创建时的登录令牌。
- 传输断开后，后端保留原 PTY 300 秒。前端按 0.5～15 秒退避重试；网络恢复、页面重新可见时也会尝试恢复。
- 恢复连接继续使用原 shell，不重发键盘输入，不重新执行命令。会话已经过期、登录失效或服务重启时明确显示结束，需要新建终端。
- 服务每 15 秒发送应用层心跳；浏览器在可见状态连续 60 秒没有收到消息时更换连接。后台页面恢复可见时检查连接。底层 WebSocket 的 ping/pong 保持启用。
- 正常 shell 退出与传输故障分开处理；退出不触发新建 shell。

## 输出与输入

服务端发文本 JSON 控制帧（`terminal.ready`、`terminal.ping`、`terminal.exit`）；二进制输出帧前 8 字节是大端累计字节偏移，其后为原始 PTY 字节。客户端向 xterm 提交输出后才确认对应偏移，重连携带最后确认的位置，并丢弃重叠输出。

客户端键盘输入仍使用文本帧，原有 `ESC[resize:行x列` 用于尺寸调整。客户端控制消息使用二进制 JSON（`ack`、`pong`、`close`），不会写入 shell。

每个 PTY 最多保留 1 MiB 未确认输出，达到上限暂停读取，由 PTY 向产生输出的进程施加背压，收到确认后继续。输入排队上限为 1 MiB，处理非阻塞写入的部分成功情况。每个登录最多 8 个会话，服务总计最多 32 个。

旧前端仍可使用原始字节协议，其断开时立即清理，不支持恢复。新协议的恢复窗口只用于短时传输故障，不跨服务重启，也不跨整页刷新保存会话 ID。

## 排查

查看 `journalctl -u rk3588-console.service` 中 `[Terminal]` 记录，包括会话 ID 前缀、创建的 PID、连接/恢复、断开码、异常类、累计输出、待确认字节、存活时间和清理原因。自定义日志不记录命令、终端内容或登录令牌；分享系统访问日志前仍须隐去 URL 中的 token。

断开码 1006 表示没有正常完成关闭握手，不能仅凭该码断定是网络、浏览器还是其他环节。结合服务重启、登录状态、断开前待确认输出量和恢复结果进一步判断。

## 验证

后端：`cd web_console/backend && python3 -m pytest tests/test_terminal_sessions.py tests/test_auth_clock.py -q`

前端：先构建，再执行 `cd web_console/frontend && python3 -m pytest tests/test_terminal_connection.py tests/test_terminal_fixes.py -q`。

后端测试使用独立登录和真实 PTY，覆盖原进程恢复、输出背压、会话过期、登录隔离、登录撤销、连接替换、心跳和正常退出。浏览器测试覆盖重连偏移、重复输出、输入不重放、显式关闭及结束后不再重连。
