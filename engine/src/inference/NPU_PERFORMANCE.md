# NPU 性能回归（2026-10-26）

本页为较早的输出/锁优化实验归档；之后的全局核心分配修正不采用这些被撤回的改动，见
[自动核心分配对照](../../../docs/npu-core-placement.md)。下文“恢复”“当前运行”均指本轮历史实验结束时。

**结论：候选优化未通过严格的全通道发布性能验收，已撤回源码，运行版本恢复基线。现有全模型防冲突保护和三核并行保留。**

本报告记录已撤回候选的实验，不代表当前运行版本采用了以下优化。本次对比基线是此前已部署、可稳定运行的共享核心调度版本。候选保留同核 SDK 生命周期保护、不同核心并行和公平排队。没有调整权重、输入尺寸、阈值、视频、worker 数、限帧、NPU/CPU 频率或绑定策略。

候选变更（已撤回）：只唤醒能取得核心的请求；SDK 输出释放后立即交还核心；YOLOv8 检测和 YOLOv5 分割读完原始张量后，在核心锁外完成 NMS / 掩码；YOLO26 Pose 与深度模型使用原有输出内存，在核心锁外完成后处理。输入的 CPU 内存复制和深度输出池申请也移到申请核心之前。

曾测试整张输出预分配方案，但没有稳定收益且 CPU 开销上升，已撤回；不在最终版本中。

## 方法

每种场景按旧→新→新→旧顺序执行。每次预热 15 秒、采样 60 秒，丢弃跨越预热边界的日志窗口；按实际窗口时长加权计算 FPS、按成功帧数加权计算耗时。RTSP TCP 客户端持续解码，输入均为同一 MP4 循环视频。每路 3 worker，queue_size=1，max_fps=25；仅测试 RTSP 端口改为 18554。

`infer_fps` 是成功完成的帧/批次，`publish_fps` 是通过现有帧序号检查写入结果槽的次数。`queue+worker` 从入队到推理处理完成，不包含解码前、后续业务逻辑和网络播放的延迟。相同视频的不同线程完成顺序会影响旧结果丢弃，所以发布率需要独立观察。

## 双路与同帧六模型

| 场景 | 旧推理 FPS | 新推理 FPS | 旧发布 FPS | 新发布 FPS | 旧 queue+worker ms | 新 queue+worker ms |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| ZipDepth 768×768 | 7.37 | 7.40 | 6.77 | 6.74 | 422.52 | 419.67 |
| YOLO26 Depth 640×640 | 7.38 | 7.38 | 6.70 | 6.65 | 422.38 | 420.65 |
| 同帧六模型，640/768/1088 | 5.30 | 5.35 | 5.30 | 5.35 | 588.79 | 581.61 |

双路推理吞吐基本持平；发布率加权变化分别为 -0.52% / -0.75%，两次单轮对比方向相反。六模型组合推理/发布吞吐 +0.86%，排队与处理平均耗时 -1.22%。这些小幅差异不应解读为确定的加速倍数或所有指标严格零波动。

双路进程 CPU 使用率均值约 273.0% → 269.4%；同帧六模型约 213.3% → 213.4%（100% 表示一个 CPU 核心）。

## 六路独立视频与拒绝原因

| 通道/模型 | 旧推理 FPS | 新推理 FPS | 旧发布 FPS | 新发布 FPS | 发布变化 |

合计推理吞吐 33.239 → 33.399 FPS，合计发布吞吐 31.573 → 31.701 FPS。合计值掩盖了通道 02 的下降：两次单轮发布率分别为 5.400 → 5.036 和 5.295 → 5.268 FPS，加权平均下降 3.67%。通道 03/04 的加权发布率也低于基线。虽然完成顺序和旧结果丢弃会产生波动，仍没有足够证据满足用户“无性能损失”的严格要求，因此不部署此候选。

六模型全部固定核心 0、18 个上下文另持续运行 60 秒，零推理失败，RTSP 解码 1770 帧，正常退出耗时 1.219 秒。这证明本次候选的调度回归通过，但不能抵消发布性能验收未通过。

最终恢复基线的 SDK 生命周期锁和输出处理方式；只保留对比脚本、本报告、原始日志和已撤回源码快照。后续候选须同时审查每路成功推理、实际发布和延迟，不能靠平均/合计值宣布全通道无损。

## 验证范围

候选阶段 9 项调度、异常、跨进程占用和构建检查通过，包括提前释放后另一上下文可立即工作、重复释放不会破坏后续占用、81 种核心掩码配对、停止/故障唤醒。六份现有权重分别通过三个同核实例的普通输入和 DMA 输入回归（每份 48 次调用）。

现有权重覆盖 YOLOv5 检测、YOLOv8 检测、YOLO26 Depth 和 ZipDepth。缺少 YOLOv8 Pose、YOLO26 Pose、YOLOv5 Seg 权重，无法给出这三类真实网络的性能结论；编译及公共调度回归不能代替它们的实机测试。

  --baseline /path/to/baseline --candidate /path/to/candidate \
